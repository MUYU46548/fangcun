## 一句话

这一版把方寸从「能用」推到「出错能查、时间能排、功能都有入口」——
修掉 11 个真实缺陷，补上崩溃日志与三类自动守卫，日历支持时间段并与待办联动。

## 升级说明（重要）

- **数据不动**：数据目录、`task-data/`、`registry.yaml`、备份格式全部兼容，直接覆盖安装即可。
- 任务文件新增了一个**可选**字段 `开始`（`start`），与「截止」组成时间段。
  老任务没有它不受影响；用 Python CLI 写过的任务文件也已被两侧同步识别。
- 升级前建议先做一次「立即备份」（设置 → 备份）。

## 三条主线

### 1. 出错终于能查了

以前任何失败都只有一句干巴巴的提示，终端里只有 vite 的噪声——**真因无处可寻**。本版补全：

- **应用日志**：`%APPDATA%\fangcun-desktop\logs\fangcun-YYYYMMDD.log`，
  记录主进程崩溃、未处理 promise、渲染层异常、**每一个 IPC 通道的失败（带通道名与堆栈）**。
  日志文件按天分、自动轮转、保留 14 天，且**写日志本身永不抛异常**。
- **顶栏错误条**：出问题时界面上就会出现一条可点开的红色提示，点「查看日志」直接看尾部内容，
  点「打开日志目录」跳到文件。设置页新增「诊断日志」区块（路径 / 打开 / 复制）。
- **启动台失败会带上命令**：不再只有"启动失败"四个字一行糊过去。

### 2. 交互缺陷收口（用户实测报障）

| 报障 | 真因 | 现在 |
|---|---|---|
| 按钮样式仍为默认 | `.ghost/.pri/.ok/.danger` **只在特定容器下定义**，待办/日志/日历里的按钮匹配不到任何规则 | 补了与容器无关的全局按钮基座；并加自动守卫，往后"用了 class 却没全局样式"会被构建前拦下 |
| 日志改不了项目 | 更新日志时**只回写了标题/内容/下一步**，`项目` 与 `关联任务` 被静默丢弃 | 四个字段一起回写；项目改下拉选择，关联任务按所选项目过滤后选择，也可手填 |
| 拖动文件时提示疯狂闪烁 | 提示是插入文档流的元素，一出现就把内容顶下去 → 光标位移 → 提示消失 → 又出现，自激振荡 | 提示改为固定悬浮层，且不参与鼠标命中 |
| 拖入同名文件毫无提示、会重复生成 | 导入前不判重 | 按「**文件名 + 正文内容指纹**」判重，一次性告知跳过几个、为什么跳 |
| 点「阻塞」页签报 `loadBlockerChains is not defined` | 那个函数**从来没被定义过**，页面直接停住 | 补上实现；并加守卫，往后"调用了不存在的函数"会在提交前被抓出来 |
| 启动台加的应用启动失败 | `.bat/.cmd` 不能直接启动（必须经 cmd.exe），而示例配置里三个是 `.bat` | 执行器重写：目录/快捷方式交给系统打开，`.bat/.cmd` 走 cmd，`.ps1` 走 powershell，`.exe` 直接启动；并且**等到真的起来才回报成功**，失败原因带命令一起给你 |
| 日历跟任务/待办不联动、没有"指派时间"、看着不支持跨月 | 日历只读任务、只认单日截止、其它月份全塞进「未安排」 | 见下 |

### 3. 日历：时间段 + 与待办联动

- **时间段**：任务新增「开始」字段，与「截止」组成区间，日历上画成跨天连续色带。
- **待办上日历**：待办设置到期日后会出现在日历上（可开关），与任务用颜色区分。
- **四处指派入口**：任务卡右键 →「📅 指派时间」、任务详情 →「📅 指派时间」、
  待办条目的 📅 按钮、以及「未安排」区域直接点条目。
- **跨月**：其它月份的任务单独成组，点一下直接跳过去，不再混进「未安排」当垃圾堆。
- 拖动：单日任务拖到某天改截止；时间段任务拖动则**整体平移**（长度不变）。

## 新增入口（原本功能写好了却没入口）

- **📋 复制为提示词**：日志卡片与日志详情都能一键复制成可直接粘给 agent 的提示词块。
  这本来是方寸的核心动作（日志 = 提示词暂存与传递的主战场），此前后端接口齐全却没有按钮。
- **✅ 验收裁决**：任务处于「待验收」时，任务详情与右键菜单出现正式裁决入口
  （通过 / 驳回并写理由），不再只能靠"直接完成/驳回"跳过流程。
- **📄 文件**：任务详情可直接在文件管理器中定位该任务的 markdown 文件。
- **最近备份所在目录**：备份区新增入口，直达最近一次备份文件。

## 开发者相关

- **开发态改主进程/preload 会自动重启 Electron**。此前 `npm run dev` 只有渲染层热更，
  改了主进程不重启就会进入"界面是新的、通道是旧的"状态，表现为一堆莫名其妙的错。
- 新增/升级的自动守卫（提交前应全绿）：

  | 守卫 | 抓什么 |
  |---|---|
  | `check-ipc-parity` | 僵尸按钮 / 僵尸通道 / 未接线模块 |
  | `check-template-bindings` | 模板引用未声明、**调用了未定义的函数**、**定义了却零引用的函数** |
  | `check-button-styles` | 按钮用了 class 但没有全局样式 |
  | `e2e-*`（9 套） | 数据层 224 条 + 主进程 418 条断言，含**真实启动 .bat**、日历跨月算术、日志判重指纹 |

- 顺手修正了两个"验证器自己在说谎"的问题：IPC 对账把从不加载的假入口当真入口；
  渲染层 e2e 在拿不到结果时静默通过。

## 已知限制（不藏着）

- **渲染层真点击测试**需要桌面会话才能跑；无窗口的受限环境会自动跳过（不算通过）。
- 安装包未做代码签名，Windows SmartScreen 可能提示"未知发布者"，选"仍要运行"即可。
- 「清理超期」只把过保留期的已完成日志标为「已归档」，**不会删除任何文件**。
- 同名判重是启发式的：内容被实质改写（哪怕只改一个字）就会放行。
- 自动更新尚未配置发布渠道，更新按钮不会联网检查。
- 与 Agent 的联控、项目全周期管理**仍未开始**——本版只保证"任务收口 + 方针载体"这条线可用。
