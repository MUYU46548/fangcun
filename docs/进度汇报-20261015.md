## 一、启动台（你点名的第 1 件）

### 一句话裁决（沿用 10-14 的结论）

**不是 Bug，是两条线接错了**：`apps.json` 里「绒花墨坊」把 **vite dev server 的 8090**
登记在**打包好的 Electron exe** 上。点启动台只开一个桌面窗口，它本来就不监听 8090。
服务页却给一个「▶ 启动」，你点完仍是「空闲」→ 又一次得出"启动台坏了"。
根因是 **`port`（对外提供哪个端口）与 `cmd`（点一下会跑什么）被混成了一个概念**。

### 修了什么

| # | 改动 | 位置 |
|---|---|---|
| 1 | **卡片点正文 = 启动**（原来点正文是"编辑"，启动要单点小按钮 —— 正好反着）；编辑挪到卡片右侧独立的 `✏️ 编辑`，另加 `📁` 打开所在文件夹 | `App.vue` 启动台模板 |
| 2 | 服务页把**「启动命令」摊开显示**（连 `cmd` 是 .exe 还是 .bat 都讲清楚） | `portRegistry.ts` 回传 `cmd` + `App.vue` |
| 3 | 端口登在**桌面程序**上的行给出**诊断**（`launchpadDiag.ts` 纯函数）：说清"桌面程序通常不会监听这个端口"、并给两条出口（改命令 / 去掉登记）。**只提示不阻断** | 新增 `desktop/src/shared/launchpadDiag.ts` |
| 4 | **启动后按事实复查**：主进程拉起后 2.5s 再查一次真监听，回传 `listeningAfter`；没起来 → 界面明说「已拉起 X，但 8090 仍无人监听，这条登记接错了」，按钮期间显示「启动中…」 | `portRegistry.startService()` + `App.vue` |
| 5 | **数据收口**：`userData/apps.json` 里「绒花墨坊」的 `port:8090` 摘掉（改描述），该端口改记进 `services.json` **手填清单**并注明"只有开发时手工跑 vite 才有"。改前两份文件都留了 `.bak-fangcun-portfix-*` | `%APPDATA%/fangcun-desktop/` |

### 「确保以后不再发生」= 四道机制（不是一句口号）

1. **静态诊断**（提前拦）：`diagnosePortRegistration()` 把"启动形态 × 端口"分类成
   `ok / suspect / none`，判据只认机器码（`exe-cmd` / `script-or-dir` / `no-cmd`…），不认文案。
   ⚠ 它**刻意不报警告式结论**（不许出现"失败/坏了/无法启动"），因为静态看不出真因。
2. **结果核对**（事后兜底）：不管静态怎么判，"拉起了但端口没起来"这件事**只由事实认定**。
3. **可看见**：服务页 + 启动台卡片都把"启动命令"摆在明面上 —— 此前只能靠猜。
4. **断言 + 反例**：
   - 新增 `scripts/test/e2e-launchpad-diag.cjs`（**36 条**，含"脚本类一个都不许被判 suspect"的过度报警反例）；
   - `e2e-renderer-web` 新增 **17 条**（点卡片=启动且**不**弹编辑框、编辑按钮**不**触发启动、
     exe 行有诊断而 .bat 行没有、手填登记不显示 `cmd`/诊断、拉起但没起来时必须报错条并给下一步）；
   - 反例自证 4 次（见文末「验证」）。

## 三、真点击层：首次全绿（316 / 0）

本轮把 `e2e-renderer`（真 Electron + 真点击）从 **299/10** 跑到 **316/0**。分三类：

### A. 两条**真 bug**（都是"界面在说假话"这一类）

1. **设置弹窗开着时按 Esc 什么都不发生** —— Esc 只认「弹窗里的 `.acts .ghost` 取消按钮」，
   而设置面板没有这个按钮。更隐蔽的是：设置遮罩在 DOM 里排在待办弹窗**后面**，
   于是"关不掉"表现为"待办弹窗关不掉"（其实是去关一个关不动的）。
   **修法**：没有取消按钮时，兜底派发一次 `mousedown` 到遮罩本体，走它自己的 `@mousedown.self`。
   **断言升级**：故意同时开着「设置 + 待办编辑」→ 按 Esc 必须关掉**更上层**的设置、待办留着；再按一次关待办。
2. **顶栏页签选中态对比度检测读歪**（详见下条"探针 bug"）——由"逐元素读值"改成"按 CSSOM 声明值复算"。

### B. 三条**测试自身 bug**（长期红 = 没保护）

| 断言 | 真因 | 修法 |
|---|---|---|
| 备份包"独立 Python 工具"5 条校验 | 工具路径拼成了 `scripts/scripts/fangcun-restore.py`（`__dirname` 已是 `scripts/test`）——**这 5 条从来没真跑过** | 路径修正 → 现在真跑，97/0 |
| applog 通道注册 | 断言还在要 `applog:dir`，而它 **2026-10-11 被有意删除**（与 `openDir` 重复） | 从期望列表移除 + **反向断言**"不许长回来" |
| 服务页"按条数渲染 2 条 / 登记后 3 条" | 夹具写死数字（本次往夹具加了一行就假红） | 期望值改成**从夹具真身算** |

### C. 五条**过期断言**（量的是旧设计）

- 完成/驳回列默认折叠 → 改判"**DOM 折叠集合 == 该偏好**"（无键→默认；有键→尊重显式值）。
  原写法依赖 localStorage 跨轮残留，设计上就"显式值优先"，于是长期红。
- 待办卡片网格 3 条（要 flex + 优先级在第一行右端）→ 待办卡 2026-09-29 被拍成**两行卡**、
  之后网格又改成 CSS Grid；改按现行设计断言（是网格多列 / 标题 3 行不截断且独占一行 / 优先级在卡上）。
- 列表视图分区折叠 → 复查时"取第一个还有可见行的分区"，折叠完就指到下一个分区去了；改成**认分区名**。
- 悬停轻提示 → 旧版直接改 `.ttl` 的 textContent，那节点归 Vue 管、一重渲染就被覆写回真标题（恒红）；
  改成**改夹具真身**（setTasks）+ 切走再切回看板触发重渲染。
- 顶栏页签对比度 → 见下。

### D. 一处**探针 bug**（产品是对的）

本环境的 `getComputedStyle` 对顶栏页签的读值**自相矛盾**：带 `.on` 的那个报白色底、
**不带** `.on` 的反倒报品牌紫底（12 个页签逐条打印过）。而同一份 CSSOM 里规则就在、
`docs/views-web/board-cols.png` 截图里也是正常的紫底白字 —— **产品是对的、探针读歪了**。
→ 页签不再走"逐元素读数"，改为**按 CSSOM 声明值复算**对比度（`.vbtn` / `.vbtn.on` + `:root` 的 `--accent`/`--muted`），
比原来更硬：谁把 `.vbtn.on` 改坏都会当场红（已用"底色改白"注入验证）。

## 四、你问的：**为什么还在天天丢内容、方寸的作用没到位**

盘完这本账 + 修完这一轮，原因有六条，按"能不能靠方寸解决"排：

**① 方寸只收自己的卡，别的线不往里写（最结构性的一条）**
registry 里 13 个项目，但此前 112 张卡几乎全是方寸自己的事。司天 / 绒花墨坊 / 记忆圣所 / 明鉴的活
活在**各自的 agent 对话里**，方寸只是"看得见项目名"，收不到它们的事。
→ 方寸的设计目标是"统一任务入口"，但**缺一个入口动作**：别的 agent 不写它。
本轮补上了第一块（账本 47 条 → 65 张卡），但那还只是"手工搬一次"。

**② 账本本身只是一个 md 文件（已修）**
它盘点得很完整，但没有任何机制保证被读、被跟进 —— 对话流一冲就没了。本轮落成卡后，
它至少变成了"能被方寸筛出来、能被派活、能关账"的东西。

**③ "回字"没落卡 = 卡着下游 15 条活**
账本 C 表那 11 件全是"回一个字 / 点一下"级。决策卡的机制（回字当轮立卡）10-12 就装好了，
但**第一单真活没人跑过** —— 所以到今天还是靠你记。

**④ 群聊记录两周即焚（结构性，方寸治不了全部）**
账本实测：9-30 以前的对话原文不可达。任何**没当轮落进文件**的拍板，两周后连"你说过"这个事实都消失。
方寸能做的是"当轮一句话落卡"的最低摩擦入口（`⚡ 快速记` 其实早就有了）——
问题不在工具，在**没人用它**。

**⑤ "做了" ≠ "到过你手里"（未达栏）**
仓库一路在发版，但你的世界没发生过。缺的是**回执**。方寸有「验收」字段与执行日志，
但没有强制回写 —— 这一栏本轮已作为一张卡收进方寸，但它需要机制、不是需要卡。

**⑥ 长期红的断言 = 没保护（本轮清了 6 条）**
真点击层长期红着 6 条，其中 3 条是"环境/夹具"，2 条是测试自身 bug，1 条掩护了一个真 bug。
红着没人看，等于这一层不存在 —— 这跟"内容会丢"是同一个病：**看起来有保护，其实没有**。

**小结论**：方寸这个工具本身没大毛病，缺的是**三根管子**——
(a) 别的 agent 的写入管，(b) 回字当轮落卡的习惯/触发，(c) 交付回执。
本轮通了 (a) 的一半（账本搬进来 + 幂等守卫），(b)(c) 要你先拍板怎么落。
