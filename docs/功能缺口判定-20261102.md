## 判定依据

### ① 启动台空壳 —— 部分

读了 `desktop/src/main/launchpad/executor.ts` 全文（317 行）。分支事实：

| 目标类型 | 当前实现 | 行号 |
|---|---|---|
| `.exe` 无参数 | `launchViaExplorer` → `spawn('explorer.exe', [target])`，之后 `launchAndVerify` 用 `listImagePids` 前后快照差集复查 | 117-150 / 203-217 / 274-278 |
| `.exe` 带参数 | `spawnAndWait` 直接派生（explorer 传不了参数） | 275-277 |
| `.lnk` / 无扩展名 | `openViaShell` → `shell.openPath` | 267-269 |
| `.bat` / `.cmd` / `.ps1` | `cmd.exe /c` 或 `powershell -File`，由本方进程拉起 | 285-295 |

`e2e-launchpad.cjs` 本机实跑 21/0，其中三条直接针对本次修法：

```
PASS  .exe 无参数 → 交给 explorer 代启动（不再由本方进程树派生）
PASS  .exe 无参数 → 不再走 shell.openPath（那条路会继承父进程 job）
PASS  源码守卫：listImagePids 不做映像名比对（只信 /FI 的过滤结果）
```

用户当前登记的两条都在已修分支上（`%APPDATA%\fangcun-desktop\apps.json` 实读：`E:\Software\SiTian\SiTian.exe`、`...\绒花墨坊.exe`，均无 args）。

判「部分」的理由是代码事实，不是印象：`browseFile` 的文件选择器把 `lnk / bat / cmd / ps1 / com` 全部列为可选类型（`desktop/src/main/ipc.ts:360-365`），而这五种类型仍走卡片自己认定的病根路径（父进程在方寸的 job/进程树里）——`.lnk`/无扩展名走 `shell.openPath`，`.bat/.cmd/.ps1` 由 `cmd.exe`/`powershell` 从本方派生。也就是说「空壳窗口」在非 `.exe` 登记上没有被覆盖。

未核实：卡自己的断点写着「没有从真实方寸窗口里点一次启动」，本次同样没有代替人去点，所以「窗口真的正常出现」这一点只有 explorer 分支的间接证据。
