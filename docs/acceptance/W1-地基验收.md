## 一、备份滚动

**怎么操作**

1. 设置 → 数据安全 → 备份：本地保留份数（默认 **5 份**，2026-10-21 从 10 调低，约 5×9.4MB≈47MB，一周回滚窗口）
2. 点一次“立即备份”，重复 6 次
3. 打开备份列表看最旧那份还在不在

**预期可观察结果**

- 备份列表恒为 5 行，第 6 次之后最旧的一份消失；
- 每次备份都落一份 manifest，被"瘦身"跳过的文件逐条记在 `manifest.omittedFiles`（不静默）；
- `backup:sizeReport` 能摊开体积构成。

**实际结果与证据**

- `node scripts/test/e2e-backup.cjs` → **123 / 0**
- 实现：`desktop/src/main/backup/index.ts`（`rotated` / `rotatedFreedBytes` 记账）、
  `desktop/src/main/backup/config.ts:77`（保留数 5 的出处与理由）
- **界面待你点**：第 2 步的连续触发与列表行数

## 二、可撤销

**怎么操作**

1. 任意改一张任务卡（改状态 / 改标题）或删一条待办
2. 立即看顶部：出现撤销条，5 秒后收起，顶栏留 `↩ N` 小胶囊
3. 等 2 分钟后按 Ctrl+Z（或点胶囊）→ 应仍能撤回

**预期可观察结果**

- 撤销条 5 秒收起但**栈不清空**（误点十分钟也能撤）；
- 每次新动作让撤销条重新展开 5 秒；
- ✕ 是"全部忘掉"，不是撤销一条。

**实际结果与证据**

- `node scripts/test/e2e-timefmt.cjs` → **58 / 0**（D19–D21 三条专钉上述行为）
- 实现：`desktop/src/renderer/undo.ts`（`UNDO_BAR_MS = 5000`、`undoStack`、`undoCount`）
- **界面待你点**：真改一张卡后看撤销条与 Ctrl+Z

## 三、自动拉取（自仓）

**怎么操作**

1. 让方寸的仓库在远端多一个提交（另一台机器 push，或手动在 GitHub 上改一个文件）
2. 重启方寸（开机同步只在这个时候跑）
3. 看日志 / 状态条里的同步结论

**预期可观察结果**

- 远端有新提交 → 落地（`state=ok`），工作区真拿到新内容；
- **本地领先或与远端分叉 → 必须拒**（`HEAD` 不动、工作区不被覆盖）；
- 没有上游 → 分到“没有上游”，不是失败也不是成功。

**实际结果与证据**

- `node scripts/test/e2e-self-sync.cjs` → **16 / 0**（真临时裸仓库跑 `git pull --ff-only`；含"本地领先/分叉必须拒"的反例，
  夹具里故意装回 `pull.ff=true` 的危险默认，否则反例假绿）
- 实现：`desktop/src/main/services/selfSync.ts`（只 `--ff-only`、`GIT_TERMINAL_PROMPT=0`、硬超时）
- **界面待你点**：第 2 步重启后的状态条文案

## 四、实况回流

**怎么操作**

1. 项目页 → 概览卡 / 主从详情，看“路线文档”那块
2. 换一个**没有 README 也没有 ROADMAP** 的项目再看

**预期可观察结果**

- 有文档：README 只取一句话摘要，ROADMAP 给"接下来做什么"；列出最近动过 `docs/` 的提交；
- 缺文档：那一格**不造空壳**，如实说缺哪一份；
- 只读：看完之后 `git status` 仍为空，文档 mtime 不变；一天一批（`cached` / `readAt` 判据）。

**实际结果与证据**

- `node scripts/test/e2e-repo-docs.cjs` → **26 / 0**（真仓库读 README / ROADMAP + `docs/` 提交；**只读**断言；
  缺一份就是 `null`；四种"读不到"各有各的话；`-c core.quotepath=false` 否则中文路径是八进制乱码）
- 实现：`desktop/src/main/services/repoDocs.ts`
- **界面待你点**：第 1/2 步的两块显示
