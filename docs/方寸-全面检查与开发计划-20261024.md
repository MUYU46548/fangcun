## 零、结论先行

**一句话：方寸这版代码是健康的，坏的是「看板说的事」和「真要你处理的事」之间那条链，以及一条没有入口验证的交付链。**

五条实测结论，每条都能单独推翻一种"再堆功能"的排期：

1. **代码基线干净**：`verify.py` **293/0**；`scripts/test/` 下 `e2e-*` + `check-*` 共 **59 个文件全绿，2 分钟跑完**。没有隐藏的红色。
2. **但"全绿"不可证伪**：`package.json` **没有 `test` 脚本**、`.git/hooks/` 是空的、**没有 CI**。59 个测试靠人挑着跑，AGENTS.md 里"全绿"的口径历史上出现过 900/1041/1209/部分 SKIP 四种数。**测试不是没有，是没有闸门。**
3. **97 张待办里只有 20 张能开工**（21%）。其余是账本镜像 41 张、他项目执行任务 27 张、索引文档 5 张、无主欠账 6 张、旧格式账本 4 张。看板在说假话，不是卡太多。
4. **三个收口机制全部造好了、上过线、从来没用过**：`阻塞` 字段 173 张卡里只用了 **1** 张（而 `BlockersView` 早就在产品里）；决策板有 33 张决策卡，另有 12 张"待拍板"仍以「待办 + 高」占着待办首屏；待审批从 10-18 的 1 张涨到 **4** 张。**工具不缺能力，缺的是把卡放对位置。**
   ⚠ 但"放对位置"不能用 `阻塞` 凑合 —— 它是任务 ID 外键，写中文会静默吞卡（§4.5）。**还有一个更底层的问题：列表字段在 TS 侧根本没有归一，39 张卡的 `项目:` 是裸标量，而写入会让它继续翻形态。**
5. **契约机制在方寸自己身上失效了**：REV-006（10-16）明文销掉「悬置：操作系统=Windows」，那张卡（`task-20261012-026`）至今仍是「待办 / 高」。REV 记了，卡没动 —— 这直接击穿验收线②「契约机制本身在方寸可用」。

**所以 0.5.0 不该是功能版。它的目标只有一个：让"方寸里写着的事"等于"真要你处理的事"。**

## 二、五个真问题（按严重度）

### P0-1 · 看板说假话：97 张待办的六类构成

| 类 | 构成 | 数量 | 判断 |
|---|---|---|---|
| A 方寸自身可执行 | 非账本 + `fangcun-base` | **14** | ✅ 主业，该收 |
| B 跨项目挂账镜像 | 账本 B 表 `[账本:20261015:B-*]` | **41** | ⚠️ 该收但**形态错**，应挂「阻塞」不占待办 |
| C agent 侧欠账 | 账本 D 表，全部「无主」 | **6** | ❌ 无主的欠账不是任务 |
| D 账本索引/总纲 | A/C/E/Z 表索引 +〔未达〕栏 | **5** | ❌ 卡上自证"这是索引，不是任务本身" |
| E 他项目真任务 | 司天 14 / ROSA 5 / 绒花 3 / 明鉴 2 / 其余 3 | **27** | ❌ 方寸不该背执行 |
| F 绒花账本旧格式 | `账本-绒花墨坊-*` | **4** | ❌ 同 E |

**病因不是"卡多了"，是 `scripts/import-ledger.py` 做错了一件事**：它把账本里 47 条挂账一律落成 `状态:待办`，并按账本原文的紧急度标了 12 张「高」。搬运是忠实的，**落位是错的** —— 没区分"可执行"和"等待线"。契约 REV-001 原话是"台账降配件位，**只接等待线**"：接住、可见、不下沉 ≠ 接手。

### P0-2 · 三个收口机制空转

| 机制 | 现状 | 应该 |
|---|---|---|
| `阻塞` 字段 | **1 / 173** 使用 | ⚠ **不能直接往里写"卡在谁"** —— 它是 `string[]` 任务 ID 外键，写中文会让卡从 BlockersView 静默消失。见 §4.5 |

### P0-3 · 交付链：能出正确的包，但证明不了包是对的

三个失败点（按 概率×影响）：

1. **没有统一门禁**（概率 100%/每次发版）。病灶是**判据本身不稳定**：EBUSY、需桌面会话、SKIP 三项历史上反复漂移，而"跳过"和"通过"在报告里长得一模一样。
2. **构建产物与取件目录是两个地方，中间靠手工 `cp`**。构建输出 `release-<ver>`（为绕 EBUSY），发布取 `desktop/release/`（`publish-release.sh:135`）。而 `desktop/release/` 里躺着 **9 组同名前缀的 exe（0.3.4→0.4.1，770MB，文件名只差版本串）**。`release-precheck.py` 只能证明"`latest.yml` 与 `exe` 互相自洽"——**把上一版这两个文件一起拷错，它照样通过**。这是"包里是上一版"最可能的真实成因，不是 electron-builder 的锅。
3. **`npm run build` 不查 `.vue` 类型**（无 `vue-tsc`）。Vite 走 esbuild 转译，模板里错字 prop / `undefined` 属性照样进包，`verify.py` 和全部 `.cjs` 断言都碰不到（它们跑的是已编译产物，语法合法）。

### P1-4 · 冻结的"引擎"层：`App.vue` 14020 行

| 段 | 行范围 | 行数 |
|---|---|---|
| `<template>` | 1–3324 | 3324 |
| `<script setup>` | 3326–10890 | **7565** |
| `<style>` | 10892–14020 | **9529** |

占渲染层 17786 行的 **79%**。已拆 11 块（LogsView 287 / TodosView 170 / CalendarView 156 / TrashView 407 / SkillsView 607 …），都是小块。

**这里有一个计划内部矛盾必须点出来**：10-18 定的验收锚点是「单文件 ≤ 3000 行」，但拆分纪律第 4 条是「样式不跟着走」。**照现在的路径永远到不了 3000 行** —— 9529 行样式一天不外置，天花板就在 4490 行。两件事必须同时决定，不能只决定一件。

### P1-5 · 两处静默风险

- `updater.ts:15` **`autoInstallOnAppQuit = true`** —— 坏包一旦上传，用户下次退出就装上，**无灰度、无开关**。这是当前唯一"会自己扩散"的风险。
- `data/index.ts::setDataDir` **不校验目标是否落在安装目录内**，只检查有没有 `registry.yaml`/`task-data`。便携态（数据根落在 exe 同级）下，NSIS 覆盖安装会**直接抹掉数据**。

### 4.5 ⚠ M2 的技术前提：`阻塞` 是外键数组，不是备注栏

> **本节是二稿补写的，初稿这里是错的**：我原来写「51 张挂账改挂 `阻塞`，字段里写明"卡在谁"」—— 把 `阻塞` 当成了备注栏。产品组去读 `getBlockerSources()` 的实现才发现它是 `string[]` 任务 ID，写中文会让卡**静默消失**。这是本次体检自己犯的第一个错，记在这里免得下次重犯。

**这一节是本次体检里最容易被写错、且写错后静默失败的一处，必须在动手前定死。**

**事实（已逐层核实）**：
- `阻塞` 字段类型是 `blockers?: string[]`（`data/tasks.ts:250`），存的是**任务 ID**，不是文字。
- `getBlockerSources()` 逐条 `taskMap.get(bid)`，**解析不到就 `continue`**（`tasks.ts:1093-1095`）。写中文进去不会报错，只会让那张卡**从 `BlockersView` 里彻底消失**。
- `core.py` 有 `_as_list()` 兜底，**TS 侧没有对应物**（`grep asList|toStringArray` 在 `main/data/` 与 `shared/` **0 命中**）。
- 存量 `项目:` 字段两种 YAML 形态并存：flow list **94** 张、**裸标量 39 张**、空 18 张。
- **形态会持续再生**：`renderTask` 用 `yaml.dump({flowLevel:-1})` 写块列表，Python `render_task` 写 flow list —— **同一张卡谁最后编辑它，风格就翻一次**。
- 后果：一旦把 `阻塞:` 写成裸标量 `task-xxx`，`for (const bid of task.fm.blockers)` 会**逐字符**迭代 → 凭空造出十几个假阻塞源 → BlockersView 一屏垃圾。Python 侧 2026-09-29 已因此把 `项目:` 写成过 `[f,a,n,g,c,u,n]`（`core.py:557` 注释有记录）。

**所以 M2 的动作顺序不能颠倒：**

```
① 列表归一（半天）  TS parseTask 补 _as_list 等价物，把 项目/阻塞/标签 统一成数组
② 加守卫（半天）    同一张卡，Python 与 TS 读出的这三个字段必须「都是数组且内容相同」
                    现状：修完前跑红（39 张裸标量），修完同绿
③ 才开始 M2 落位    51 张挂账迁移
```

**"卡在谁"用什么表达 —— 三选一，需拍板：**

| 方案 | 做法 | 代价 | 判断 |
|---|---|---|---|
| **A 占位卡** | 每项目建一张「等待线」占位卡（`状态:草稿`，不占待办），51 张的 `阻塞` 指向它 | +5~6 张卡、51 次字段写入 | `BlockersView` 首次有真数据，且直接回答它设计要回答的问题（"解它一次放掉 17 个"）。语义偏"任务挡任务" |

### 5.3 分层依赖规则（可写成守卫）

| 层 | 允许依赖 | 禁止 |
|---|---|---|

1. `shared/**` 不得出现 `from 'electron'`、`require('fs')`

4. `renderer/**` 调 `window.api.xxx` 的每个 xxx，必须能在 `preload/index.ts` 找到同名暴露（这条已有 `check-ipc-parity` 的三方对账，扩到渲染层即可）

## 七、决策与权衡（含两处裁决）

### 7.1 裁决一：`App.vue` 拆不拆？—— 架构组与产品组正面冲突

| | 主张 | 论据 |
|---|---|---|
| 架构组 | 四刀切分是主线 | 14020 行 = 一次误改同时影响看板/日志/设置/项目页；这是**改动风险**不是风格 |
| 产品组 | 本版不做 | 拆完不产生任何用户可见验收，且污染本版全部回归面 |

**裁决：采纳产品组"不做后三刀"，但采纳架构组"样式外置必须做"（= M7，独立里程碑、并行、不占关键路径）。**

理由三条：
1. 0.5.0 的改动集中在**数据操作 + 主进程服务**（M1/M2 是改卡状态、M3/M4 是加脚本、M5 是数据+文档、M8 是 LLM 链路）。真正要动 `App.vue` 的只有 M6 撤销。
2. 样式外置（9529 行）是**纯机械动作**：不碰状态、不改逻辑、像素可用现有两层验证（真点击 312 + 无头 572）。它一刀就能把 App.vue 从 14020 砍到 ~4500，是性价比最高的一刀。
3. 后三刀（浮层 / 领域 / 视图）会触碰**状态归属**，动了就要整体重测，应该等 0.5.0 的功能落定后再做 —— 排 0.6.0。

**同时修正一个计划内部矛盾**：10-18 定的「App.vue ≤3000 行」与「样式不跟着走」互相矛盾，照原路径永远到不了 3000。0.5.0 的锚点改成 **≤5000 行**（做完样式外置即可达成），0.6.0 做完后三刀再追 3000。

### 7.2 裁决二：Python CLI 与 Electron 双栈 —— 资产还是负债？

**判为：资产，但边界必须写死。** 依据是契约①「桌面为主产品，Web/CLI 只作 agent 通道与只读镜像」—— 这条已经定了，但代码没守住：`tegula/core.py` 有完整的写能力（`write_task_file`、`REGISTRY_PATH` 写入），`web.py` 711 行是个**能看的 Web UI**（契约说"不再投入 Web UI"）。

**裁决：不合并、不重写，但加一条守卫** —— `tegula/` 只许操作 `task-data/` 与 `registry.yaml`，不得出现对项目 repo 的写调用（当前实测**没有**这类写调用，是为守住，不是为了修）。`web.py` 保持只读镜像，不再加功能。

### 7.3 被否决的方案（记下来免得再吵）

| 方案 | 否决理由 |
|---|---|
| 引入 `vue-tsc` 做渲染层类型检查 | **有条件否决**：先试 1 天。它能抓模板错字 prop，但 14020 行单文件会报出成百上千条历史噪音，等于先要一次大清理。0.5.0 不做，0.6.0 样式外置后再评估 |
| 引入 Pinia 重构状态 | 否决。336 个 `ref` 里绝大多数是"某视图的局部状态 + 几个 handler"，按 Pinia 重排等于同时改状态归属与渲染路径，红了分不清是谁 |
| 用 vitest / playwright 重写现有 59 个测试 | 否决。现有断言质量很高（大量反例自证），重写是净损失，收益只在"生态好看" |
| 把 Python 层并进 Node | 否决。零依赖是这项目的核心卖点，Python 标准库的 CLI 是 agent 通道唯一不依赖 node_modules 的入口 |
| 上 GitHub Actions 托管 runner | 否决（硬约束）。Windows GUI 真 Electron 真点击跑不了托管 runner：无桌面会话、无 `--no-sandbox` 权限。**替代方案见 §8** |
| 加监控/告警系统 | 否决。这是单机桌面应用，没有服务端。它的"监控"就是 `app.log` + 启动自检，不该按互联网服务那套加 |

## 八、测试与发布：怎么建闸门

### 8.1 「59/0 全绿」到底证明了什么

**证明了：数据层契约、主进程服务的纯逻辑、IPC 三方对账、渲染层几何与交互，全都没有退化。**

**没证明：**
1. **类型安全** —— `.vue` 无类型检查。
2. **真机行为** —— 大部分测试用 electron 桩；真点击只覆盖 `e2e-renderer` 的 312 条，且它需要桌面会话（受限环境自动 SKIP）。
3. **打包产物** —— 断言跑的是 `dist/`，不是 `app.asar` 里的东西。
4. **"没跑" 这件事本身** —— 没有闸门，所以"今天跑过了"无法证明，也无法证明"跑的是哪 59 个"。

### 8.2 门禁设计规格（`scripts/gate.cjs`）

```
输入：无（默认全量）；--only <pattern> 可选
流程：
  1. 发现：glob scripts/test/{e2e,check}-*.cjs  → 排序后得到固定清单
  2. 并行：默认 4 并发；e2e-renderer 单独串行排在最后（它要独占桌面会话）
  3. 每个子进程：异步 spawn（本机 spawnSync 一律 EBUSY，禁用）
     超时 = max(60s, 该文件历史中位数 × 3)；超时判 FAIL 不判 SKIP
  4. 结果归一化：每个文件只报三种终态 PASS / FAIL / TIMEOUT
     ⚠ SKIP 必须降级成 PASS-with-reason 并在汇总里单列，
        不许和 PASS 混在一起显示（历史上"跳过"和"通过"长得一样是最大问题）
  5. 断言计数：每个测试必须输出 `RESULT n / m` 行（现有 59 个已全部遵守）
     汇总求和，与 scripts/test/baseline.json 里的基线比对
  6. 退出码：任何 FAIL/TIMEOUT → 1；断言总数 < 基线 → 1（这是"只增不减"的自动校验）
  7. 输出双读：人类看彩色表格；AI 看 --json 单行 JSON（含每个文件的 pass/fail/time）
```

**`baseline.json` 是这套设计的关键**：它把"断言只增不减"从"人记着"变成"机器比对"。
第一次由人跑 `gate.cjs --write-baseline` 生成，之后**只能涨不能跌**；要跌必须在提交说明里写明理由并显式改基线（留痕）。

### 8.3 CI 的现实边界

**硬约束**：Windows-only + 需真 Electron 真点击 GUI → 托管 runner 跑不了。

**推荐：三层本地闸，不建 CI。**
1. **pre-push 钩子**（`.git/hooks/pre-push`）：跑 `gate.cjs --fast`（排除 `e2e-renderer` 与所有 10s+ 的，约 40 秒）。**这是 59 个测试从"靠人记"变成"推不出去"的关键一步。**
2. **发布脚本内嵌**：`release.cjs` 出包前必跑 `gate.cjs --full`，不过不出包。
3. **发版后**：`publish-release.sh` 已有的两道闸（`release-precheck.py` + `--verify-release` 读回远端比对）**保留原样** —— 这是这堆脚本里质量最高的一处。

### 8.4 发布链要改的三处

| 处 | 现状 | 改法 |
|---|---|---|
| 三环境变量靠人记 | 只写在 AGENTS.md | ① `ELECTRON_OVERRIDE_DIST_PATH` 与镜像写进 `desktop/package.json` 的 `build` 段（electron-builder 正式配置键，随 git 走）；② 剩余的由 `release.cjs` 在 `spawn(env)` 注入，人永远看不见 |
| `release-<ver>` → `release/` 手工 cp | 静默、无报错、9 组同名 exe | **让 `publish-release.sh` 直接读 `release-<ver>`**，删掉这一步。`desktop/release/` 归档 |
| 打包前无前置检查 | 靠 10 分钟超时或 502 报错 | `release.cjs` 打包前断言：`node_modules/electron/dist/electron.exe` 存在，且其 `version` 文件 === package.json 声明的版本 |
