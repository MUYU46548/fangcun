## 一、先量现状（事实，不是印象）

窗口约 **1080** 宽（截图原尺寸 1080×675）。顶栏**一行里 14 个控件**：

```
方寸 tegula 7 条 │ 搜索框 │ ＋筛选 │ ⊞折叠全部 │ 项目▾ │ 状态▾ │ 分组·按状态▾ │ 排序·活跃优先▾
│ ＋新建 │ ⚡快速记 │ 💾 │ 🔔 │ ☑任务多选 │ ⚙
```

**直接可见的坏症状**：搜索框被压到只剩一半，占位文字「搜索…（可用 #标签 @项目」**在中间被切断**。
——"很吵"不是感觉问题，是**控件数量与字数**的问题。

**上一轮修掉的两条（这次不重复做）**：
- 「返回」按钮**不是消失，是被甩走**：`.ctrls` 一撑宽就整体换行，而 `#bar` 是
  `justify-content: space-between`，于是它被甩到上一行最右端 → 已加 `flex: none` 钉住，并有几何断言。
- 按钮文字折行 → 已加 `white-space: nowrap` + 让搜索框去伸缩。

**这次要解决的是根**：**7 个筛选/排布控件同时在一行**。要么合并入口，要么让次要项下沉。

## 二、三个方案（都已按 1080 密度画在小样里）

### 甲 · 图标化收拢 ｜ 改动小、一次点击不变

- **撤掉**「项目▾」「状态▾」两个按钮 —— 它们的功能本来就在筛选浮层里，当前值由「生效中」标签承担；
- 「分组 · 按状态 ▾」→「**⌗ 按状态**」；「排序 · 活跃优先 ▾」→「**⇅ 活跃优先**」（去掉前缀，值留着）；
- 「⊞ 折叠全部」→ 纯图标 **⊞**（title 里写全）。
- 结果：顶栏 **7 个 + 3 个全局图标**。**所有功能仍是一次点击**。
- 代价：折叠按钮只剩一个符号，需要 hover 才确认；图标符号得选一眼能懂的。

### 乙 · 只留两个入口 ｜ 最安静，多点一次

- 搜索 +「筛选 ②」+「**视图 · 按状态 ▾**」；**分组 / 排序 / 折叠全部**收进「视图」浮层（标签式选项）。
- 结果：顶栏 **4 个 + 3 个全局图标** —— 市面看板工具最常见的密度。
- 代价：切分组、折叠全部从"一次点击"变"两次"（**折叠用得频繁，这是真实代价**）。

### 丙 · 「看」与「做」分两层 ｜ 功能不减，但要往下看一行

- 第一行只放**看与筛**（搜索 / 筛选 / 按状态 / 活跃优先 / ⊞）；
- **写操作与全局图标**（＋新建 / ⚡快速记 / 💾 / 🔔 / ⚙）搬到下面的**页签行右端**（那里现在空着）。
- 结果：顶栏 **6 个**，页签行右侧 5 个。**点击次数与功能完全不变**。
- 代价：注意力要跨两行；页签行变长（但那行本来就空）。

## 三、三条硬约束（上一轮驳回换来的，任何方案都得过）

1. **顶栏只许一行**（「生效中」chips 那一行除外，且仅在有筛选时出现）；
2. **不许移动「返回」** —— 任何让 `.ctrls` 换行的方案都算不合格；
3. **视觉噪音要低**：控件数量与每个按钮的字数都压到最少；**宁可把当前值藏进 title**；
   且**不许把原生 `select` 引回来**。

## 四、我的建议

**丙 > 甲 > 乙。**
- 丙的性价比最高：**功能与点击次数一个不减**，顶栏立刻安静下来，而且它顺手用掉了页签行的空白；
- 甲次之：改动最小、最快，但顶栏仍有 7 个控件，属于"缓解"不是"解决"；
- 乙最安静，但**折叠全部是高频操作**，为它加一次点击不划算。

**可以组合**：丙（操作下沉）+ 甲的图标化 = 顶栏 5-6 个且都还能一次点到。

### 落地时踩到/修掉的三处（都不是改样式能解决的）

1. **reka-ui 的 PopoverContent 是两层**：外层 `[data-reka-popper-content-wrapper]` 才是被定位的那个
   （库内联写 `position: fixed` + transform），`class="fpop"` 落在**内层**。
   我上一轮往**内层**写了 `position: fixed` → 内层脱离外层文档流 → 外层 `min-width: max-content`
   量出 **0×0** → floating-ui 按"面板宽 0"算 `align=end`，`x = 触发器右缘`（而不是"右缘 − 面板宽"）
   → **整个浮层跑到视口外**（实测 `r=1501 > vw=1416`）。
   **正解：position 归外层（库的事），我只给 z-index（库会读走再写到外层）。**
   ⚠ 断言也必须**量外层**——量内层是假红/假绿。
2. **`#bar` 是 `justify-content: space-between`**：`.ctrls` 只按内容宽 → 标题与控件之间留一大片空白
   （实测从 x≈180 到 800 全空）。正解：`.ctrls { flex: 1 1 auto }` + 搜索框 `flex: 1`
   → **空白变成可用的搜索宽度**。
3. 新增两条几何断言把这两个症状钉死：**搜索框宽度 ≥ 260** · **`.ctrls` ≥ 顶栏宽 60%**。
   **反例自证**：撤掉撑满 → 精确红 2 条（`w=151` / `ctrls=456 bar=1416`）。
