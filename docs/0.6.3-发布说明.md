## 一、作战计划：从“能看”到“能推”

- **裁决有回执**：点“通过（冻结）/ 打回 / 改一句”后，顶部出现一条“已冻结 P1 …”，
  刚操作的卡描边闪 2.5 秒；已冻结/完成的卡按钮变成“✓ 已冻结 / ✓ 已完成”并禁用。
- **不再盲点“推进”**：没跑过判据就点“推进这一格”，会先确认“判据不过会写未完成 + 打回理由”；
  跑过判据后再推进，结果块逐条给出 通过 / 未过 / 未判定 与实际值。
- **每日推进面**（日志页顶部）：
  - 有格子可推 → “去作战计划 →”；有待裁决 → “去裁决 N 张 →”；有未完成 → “去返工 N 张 →”；
  - 空仓 / 全部完成且无积压时**不显示按钮**；
  - 全部完成不再误报“本仓还没有冻结的作战计划”；有未完成会单独报出来。
- **怎么用写进页面**：项目页 → 作战计划顶部一行说明整条回路
  （裁决 → 冻结 → 日志页看今天推哪格 → 跑判据 → 推进这一格）。

## 二、决策卡：在“做决定的地方”一键记

- 作战计划裁决后的回执条上新增 **“＋ 记成决策卡”**：预填内容（`P1 …：通过（冻结）`）、
  日期、项目、出处，一键写进决策台账；记完显示“✓ 已记决策卡 D-xxx”。
- 决策页头新增提醒：“今天已记 N 条”或“最近一条决策 N 天前（D-xxx）—— 计划卡裁决后可直接记成决策卡”。

> 决策仍由人签字：agent 直写决策的通道保持关闭（2026-10-30 边界）。
> 若要“agent 提议、你点头”，需要另开 propose-only 通道。

## 三、路线图趋势：从“一个点”到按天回算

- 每个项目多一行：近 14 天折线（蓝 = 未到终态 / 绿 = 已完成）+ 当天“活跃 / 完成 / 阻塞”数字。
- 数据按天回算：状态历史从 `.activity.log` 的 `move_status` 逐条回放，旧卡用“更新时间 + 当前状态”近似。
  **这是近似、不是审计**：窗口前已存在的卡按当前状态计入第一天（基线），悬浮提示里写明。
- 读不到趋势就整行不渲染，不画假线。

## 四、修掉的

- **待办没到点却弹“到期”**：`dueTime` 被忽略，20:52 到期的待办 17:55 就报。现在按“日期 + 时间”到点才报，
  通知正文也写出到期时间。
- **接力“本次会话 ID”文案**：新日志还没建时不存在“本次会话 ID”；改为“会话 ID（可留空）”，
  写清可填上一段的 ID 用于倒查，并新增“带入源的会话 ID”。
- **`e2e-waste` 假红**：旧断言要求 `waste-ipc.ts` 恰好 1 个 `guardedHandle`，但 `channels:get` 已并入；
  修正后 P5 计划卡的“未完成”不再被假红卡住。

  行为不变，真点击 e2e 全绿。

## 六、破坏性变更 / 升级 / 回滚

- **破坏性变更：无**。数据仍是 `task-data/*.md` + `registry.yaml`，本版没有新增数据文件或字段迁移。
- **升级**：直接覆盖安装；首次启动不需要迁移。建议升级前用“设置 → 备份”留一份。
- **回滚**：卸载 0.6.3，安装 0.5.6/0.6.1；`task-data` 原样可用（本版只新增了可选的计划/日志读取，
  没有改写旧文件格式）。
- 安装包未签名，Windows SmartScreen 会提示“未知发布者”，属预期。
