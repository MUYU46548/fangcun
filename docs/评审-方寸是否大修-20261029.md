# 评审意见 · 方寸是否需要大修（2026-10-29）

> 本件是**评审意见**，不是新方案。方案入口仍是 `docs/adr/ADR-001-方寸定位与一期范围.md`。
> 本件不改 ADR、不新增格式，只回答两个问题：要不要大修、方向错在哪。
> **性质：AI 辅助生成的产品判断草案，须暮雨确认后方可作为施工依据。**

---

## 一、结论（三句）

1. **不需要大修。** 栈、架构、数据模型、视图基座都不用动。
2. **需要一次砍 + 一次改序 + 一条纪律**：砍掉「需要别人灌数据才活」的对象扩功能；把「验收判据」提到「需求矩阵」前面；新卡立卡当轮必须带判据（不阻挡、只报红）。
3. **"反复大修"这个病，用再一次大修治不了。** 8 条 REV 里 5 条推翻前一个方向 —— 病根不是形状选错，是**没有一个对象承载"什么算做完"**，所以每个形状都验不了，验不了就换下一个。

## 二、方向错在哪：三条，都有实测数字

### ① 对象选择错了 —— ADR-001 说"抄"，落地的是"发明"

ADR-001 第 2 条白纸黑字：「主轴：抄，不自研。**格式一条都不发明**」，抄四件：ADR / User Story+AC / DoD / Milestone。

两天后的实际落地（核实于代码与数据目录）：

| ADR-001 定的四件 | 落地情况 |
|---|---|
| ADR 对象（读→改增量→存回） | **零**。全库 `ADR` 只出现在 3 个文件（`mcp/tools.ts`、`RiceMatrixView.vue`、`shared/rice.ts`），没有 ADR 对象、没有视图、没有写回链路 |
| User Story + AC | **零** |
| Definition of Done | **零** |
| Milestone plan | **零** |
| （清单外）RICE 需求矩阵 | **已实装**（ADR-002，10-28） |

RICE 池是自造格式（`rice-pool.md` 节式结构、四维取值域、P0/P1 相对分位），不在四件之内。
**这不是执行不力，是对象选错**：能看见的（页签、散点图）先做了，该先做的（判据）没动。

### ② 数据流错了 —— 新对象建好了，没人往里填

`task-data/rice-pool.md` **不存在**，真实条目 **0 条**。

这与 ADR-001 上下文自己点名的病是同一种：74 张卡是批量导入后沉底、93 张待办没人动。
判据很硬：**一个页签如果需要"别人灌数据"才活，它就不会活。** 不是 RICE 不好，是它现在没有供给。

### ③ 判定权错了 —— 173 张卡，"做完"是自报

刚核的实数（`task-data/*.md`，2026-10-29）：

| 项 | 数 |
|---|---|
| 卡总数 | 173 |
| 「验收」字段填人名（`human`/`暮雨`） | **137** |
| 状态=完成 | 60　其中正文有判据字样 | **3** |

**这是最贵的一条**：60 张「完成」里 57 张没有判据 —— 按 REV-008 自己的话，「完成」是自报（004 卡的证据门）。
自报之上再叠规划、再叠 RICE 打分、再叠复盘归因，全部是给自报排序。

## 三、对三段外部意见的判决

三段（全栈 / 梅林 / 哨兵）收敛出的分层是对的：**证据层本地零 token、推理层做可换的薄接口**。这部分我认可，且 ADR-002 之外 10-28 落的 **「对不上」页签**（`shared/mismatch.ts`：状态过期 / 引用断裂 / 完成但没判据，三类全机检、零 LLM）恰恰就是证据层的正解 —— 方向在收敛，不是散的。

但有三处要改：

### 改 ① 「独立挑刺模型」不构成分权（这是最要紧的一刀）

三方的准入线写的是：生成侧吃证据链 + 验收侧三方分权（机检 + **独立挑刺模型** + 用户终审）。

**同一个证据包、同一个供应商的模型、同一套语言，挑不出事实错** —— 它只能挑表达与自洽。
分权的判据不是"换一个模型再读一遍"，而是：

> **结论必须能在本地复算；模型只准提交证据，不准提交结论。**

只要这条立住，三方自动成立 —— 因为复算的不是"第三方"，是裁判。反过来，两个模型互审但结论仍由模型宣布，就是「验收权在模型手里」换了个皮，你们自己命名的病根没动。

### 改 ② 「终审 = 暮雨」在单人产品里是新增瓶颈

对账账本 C 表实证：**只有你能做的 10 件里，6 件是"回一个字/点一下"级，却卡住约 15 条下游 agent 的活。**
你的瓶颈是决策吞吐，不是判断力。任何要求你终审的设计，必须同时满足三条，否则等于把新瓶颈焊进流程：

- **默认通过**（不点就是过，超时自动过）
- **一段证据摘要**（不是一份报告，是三行：改了什么、机检结果、还差什么）
- **一个否决键**（一个动作能打回，且必带一句理由）

### 改 ③ 「单模型喂好证据包能到标杆几成」这个实验设计漏了供给

标杆的质量大头来自证据包（runs.db / 行号 / 三稿对照可查），这条我认。但**证据包由谁产**没人回答。
若由你产，实验必失败，且失败原因会被误读成"单模型不行"。

## 四、被漏掉的三条风险（三方都没提）

1. **判据没有产生时机。** 137 张人名验收是**存量**，不是病根。病根是**增量**：agent 建卡时没人要求它写判据，于是永远补不完。
   修法必须落在**立卡那一秒**（建卡的 agent 本来就知道自己交付了什么），而不是落在你事后补。
2. **AI 没有必经路径。** `ai-trace.jsonl` 只有 5 条记录、最后一次 10-27。按钮近零实操，更可能是**没有任何流程步骤要求此刻调用 AI**，而不是模型不好用。摆在界面上的按钮不构成触发时机 —— 这条同样适用于"插座"设计：插座要先有电器，否则只是墙上的洞。
3. **宿主单点。** 12 个视图只有一个人能维护、能灌数据、能修判据。维护带宽会挤占灌数据的时间 —— 已落地的对象会**自然腐烂**（RICE 池今天就是预演）。

## 五、该怎么做（三步，带判据，都不动架构）

### 第一步：存量分桶，不逐条重写（1 天内可完成）

不搞"137 条重写"，那是又一个要你写 137 条的死局。按状态分三桶：

| 桶 | 数 | 处置 |
|---|---|---|
| 完成 + 无判据 | 57 | **直接标「未验证」，不重写**。留痕即可，不进任何统计的正向项 |
| 活着在动的未完成卡 | 68 | 由**执行它的 agent 在动工当轮补判据**（它还知道要交付什么），你只在证据摘要上点头 |
| 已归档/沉底 | 余 | 不动 |

**判据**：`对不上` 页签的「完成但没判据」计数从 57 降到 0，且四周不回升。

### 第二步：判据写进建卡那一秒（增量治理）

`建卡` / `收卡` 两个动作里各加一次机检：卡上有没有可判定的判据（字串/数量/格式/文件存在四类）。
**没有就报红，不阻挡** —— 与 REV-008「有对象，没门禁」逐字相容，判据不能说"未写判据所以不让建卡"。

**判据**：新卡「验收 = 人名」的出现率归零（`e2e` 里加一条：建卡不带判据 → 卡上有红标）。

### 第三步：RICE 冻结扩功能，写死解冻条件

不是删、不是否 —— RICE 是你 10-24 亲拍、10-25 花钱做过原型的，池子格式也已经落地。**只是它早了**：
它排的是"值不值得做"，而"做完没做完"还没有判据。**在自报状态上排序，输出等于自报。**

**解冻条件（写死，防下一轮重新发明）**：出现 ≥1 条真实 RICE 条目，且该条目的状态可由机检复算。
在此之前不再给 RICE 扩功能、不灌演示数据。

## 七、分歧留档：「学外面做一个内置 agent 工作流」（2026-10-29 追加，**未定**）

**主张（暮雨原话）**：「我觉得学外面做一个内置 agent 工作流就完全解决我的问题了，我会觉得方寸已经做完了。」

**判断：这条主张把两件事合成了一件。拆开看，一件成立、一件不成立。**

- **成立的是体验**：你要的是「一处看完、点一下就走完」—— 不用三个窗口之间粘 md、不用记进度、不用自己拼验收。
  这个体验**不需要把编排框架搬进本体**：方寸定「阶段 → 交付物 → 判据」，agent 在外部执行，方寸收单机检。
- **不成立的是把它等同于「方寸自己出内容」**：那一步同时买三笔 —— 维护面（多角色多阶段流水线）、
  token（推理进本体）、**以及质量仍然不可判**（判据还是没写）。

**一条确定、一条不确定（分开说，不含糊）：**

- **确定**：判据缺失这条不修，内置工作流会变成**第二个规划按钮**。理由不是"内置不好"，
  是**同一个病**：产出由模型生成、判定权也在模型手里。外面这套能出好东西，是因为它出了**结构化文档**，
  不是因为它有工作流；它跑完也不告诉你"做完了没"。
- **不确定**：内置编排在单人场景下是否真的不可维护 —— **没有反例，因为没人试过**
  （你自己说过"内置＋标杆纪律这个组合没人试过"）。**我不拿"没人试过"当"不行"的证据。**

**一个能一次判定的小实验（比争论便宜）：**
把今天这套评审的「阶段 → 交付物 → 判据」落成一个模板，用**现有 MCP 通道**让外部 agent 跑一遍，
方寸只做收单机检。判据两条：① 收单能机检通过/不通过（不靠你读）；② 你全程只点三次（立项 / 收单 / 否决）。
- 跑通 → 你要的"内置体验"已经到手，剩下要不要把执行也搬进来，那时是**小决策**，不是架构赌。
- 跑不通 → 说明**判据写不出来**，那内置只会更糟：内置等于把"写不出来判据"藏进代码里。

**必须写在明处的一句**：**「我会觉得方寸已经做完了」不能当验收标准。**
这与 173 张卡里 137 张「验收 = 人名」是**同一个病**，只是从卡级升到产品级 —— 自报。
要判产品级"做完了"，只有一条：**第二使用者照同一条路径跑一遍，不看你的解释就能自己说出"这条做完了没"**
（账本里"第二使用者跑单"那件挂账，正是这条的判据）。
