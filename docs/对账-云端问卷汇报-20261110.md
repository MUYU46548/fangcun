## 三 冲突（按本地走，逐条给理由）

### 冲突 1 · 新增三态状态机 → 不新增状态

报告 §四① 要 `草稿 → 待澄清（锁） → 已澄清 → 待批准（锁） → 生效`。
本地 2026-11-09 已拍板（规格单 §3.1、D-060）：**状态表达不新增状态**。

理由：方寸的 `STATUSES` 是全局 7 态，被看板 / CLI / MCP / 统计 / 归档共用；
加两个中间态等于改所有读取方，且会让"这卡到底能不能派"有两套说法。
报告的诉求（**不过闸进不了队列**）用「`澄清:` 字段 + 写入口拒绝」同样能达到 ——
而且和 10-11 的教训一致：闸要落在动作上，不是落在标签上。

### 冲突 2 · "AI 底层走 CLI" → 已用 MCP，不另起 CLI

报告的 D4 主张 CLI 形态。方寸的 agent 面已经是 MCP（命名管道 / stdio 桥），
而报告五-3 列的「AI 版 CLI 四件套」MCP **全部满足**：参数全显式（JSON Schema）、
输出机器可读（结构化 JSON）、无状态（状态落文件）、一次一件事（一工具一动作）。
再起一套 CLI = 报告五-1 自己警告的"养了两个产品"。

**真正的缺口不是 CLI，是 GUI 侧入口**（`plan_draft` 现在只有 MCP 能调，见缺口 3）。

### 冲突 3 · 四卷档案恢复 → 等你重新拍板

报告 §四阶段〇 主张从云端保存的四卷恢复种子。本地现状：

- 四卷还在 `task-data/.trash/questionnaires-20261108-legacy/`（墨坊 12 题 + 司天 16 题 = 28 题）；
- 但同目录 `_manifest.json` 的删除理由是**「早期临时测试产物，无实际作用」**（2026-11-08 你的口径）。

两者矛盾。**不擅自把删掉的东西塞回题库** —— 恢复 / 不恢复，一句话即可（会落成卡）。

> **已了结 · 2026-11-10 21:00 暮雨拍板：不恢复。**
> 原话大意：「如果是早期测试问卷搞的东西，没什么意义，不用恢复」。
> 所以这一条从"冲突"变成"已裁决"：题库种子只从真实会话 / 真实拍板来，不从早期测试问卷回收。

## 六 几百题的真账（正面回答"做成这样够不够"）

| 维度 | 现在 | 几百题够不够 |
|---|---|---|
| 存储 | 一条一题的 md 台账，全量解析 | 够（300 条几十 KB，毫秒级） |
| 进题 | `qn_bank_import` 批量 | 够 |
| 分批 | ≤6 题/批 + `next` 取件 | 够（300 题 = 50 批） |
| 进度 | `bankStats` + 界面两处 | 够 |
| 过闸 | D-060：所有相关待答都答完才放行 | **不够宽松，但那是你选的硬度**：300 题没答完，一张规划草稿都出不来 |
| 收敛 | 未实现（缺口 2） | **不够** |
| 条件显隐 / 题目依赖 | 未实现 | **不够**（"选了 A 才追问 A1"这类现在做不到） |
| 出题质量 | 靠 agent 手写 | **最大的坑不在工程**：300 题里真"不问就会做错"的可能只有几十条，剩下是凑数 |

结论：**"能装几百题"这一轮够了；"问得准"还不够。**
下一刀不该是继续加题量，而是把「结论集」定死（缺口 2）——
没有它，"问够了没有"永远只能靠感觉，就又回到"踢一脚动一下"。
