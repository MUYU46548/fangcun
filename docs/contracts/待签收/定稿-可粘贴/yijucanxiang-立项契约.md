> 签收：2026-11-12 暮雨（回 AA（多结局已存在）A）｜ 起草：2026-10-26 企鹅（方寸侧 AI）｜ 状态：**已生效**

## 一、这是一个什么项目

**已稳定的独立游戏**（registry 原话：“已稳定、无后续开发计划”，登记在 `released:` 段）。
README 原话：“随着棋局的推进，常态将被打破。你需要在对弈中保持理智，探寻隐藏在胜负背后的真相，
并最终走向属于你的结局。”

## 二、六字段

### ① 终态形态 —— **A：已收口，维持现状，标记“已完成”**

不再新增玩法、不再排期。这一条的实质是：**这个项目进入维护态，而不是继续开发态**。

### ② 验收线 —— **A：能启动、能走完任一条线、多结局分支可到达、打包 exe 可运行**

> ⚠ **这一条被暮雨当场纠正过。**
>
> 起草时我写的原句是“能启动、能通关一条线、打包 exe 可运行（现有能力即验收线）”，
> 这个措辞**暗含“只有单线”**，而实际项目是**多结局**的。
> 暮雨回复：“AA（**多结局已存在**）A”。
>
> 实测核对（2026-11-12）**纠正成立**：
> - `AGENTS.md` 里的状态机是 `TITLE -> PLAYING -> FINALE_CHOICE -> (多分支)`；
> - `README.md` 写“最终走向属于你的结局”。
>
> 所以验收线里有两条是分开的：**“能走完任一条线”** 与 **“多结局分支可到达”** ——
> 前者保证能玩，后者保证**结局机制没坏**。只验前者会漏掉结局分支断掉这种情况。
>
> 起草失误的真因：我只读了 registry 的“已稳定”备注，**没有打开仓库看状态机**。

### ③ 不要什么 —— **A**

- 不再扩玩法；
- 不追商业化。

### ④ 选型（起草时已定）

Ren'Py（Python），打包为独立 exe。

### ⑤ 边界（起草时已定）

不引入联网依赖；存档只写本地。

### ⑥ 谁拍板

暮雨。

## 四、这条契约的实际作用

它把“这个项目**还开不开发**”这件事定死了：**不开发了，但它是成品，不是废案**。

所以以后：

- 有人提议“给它加个新结局 / 改改玩法” → 先看这份契约 ③（不再扩玩法）；
- 有人说“它好像没做完” → 看这份契约 ②（多结局已存在，能通关即可）；
- 归档讨论 → ① 已经是“已完成”，真要挪到 `released:` 段是**登记处置**，不是开发决定。
