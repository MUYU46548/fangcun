> 签收：2026-11-12 暮雨（回 AAB）｜ 起草：2026-10-26 企鹅（方寸侧 AI）｜ 状态：**已生效**
> 本文件由方寸按签收记录整理成可直接落盘的定稿；落盘动作由本仓库自己完成（方寸对外部仓库只读）。

## 一、这是一个什么项目

**ROSA 的检索层**（Python）。给 ROSA 正文与设定提供检索能力。

## 二、六字段

### ① 终态形态 —— **A：给 ROSA 提供稳定检索能力**

两种调用形态都要成立：

- **命令行**（人直接跑）；
- **可被别的 agent 调用**（MCP / 脚本）。

### ② 验收线 —— **A：20 个真实问题的人工抽查过关，并留一份基线问题集**

两条一起：

1. 对 **20 个真实问题**，命中率 / 相关性人工抽查过关；
2. **把这份问题集落盘**，作为基线。

> ⚠ 第二条不是附带要求，是这条验收线**唯一能长期成立的前提**：
> 没有基线，“检索变好了还是变差了”永远只能靠印象，**无法证伪**。
> 以后每次改检索，拿这 20 题跑一遍对照就行。

### ③ 不要什么 —— **B：可以考虑抽出通用组件给别的项目用**

> ⚠ 同样是口子，不是转向。与 ⑤ 边界不冲突：
> 通用化的是**检索组件本身**，**不是** ROSA 的正文与设定。
>
> 两条要守住：
> - **不许顺手做成“通用 RAG 框架”**（① 仍选 A：终态是“给 ROSA 提供稳定检索能力”，不是产品）；
> - 抽组件要用一次单独的决定，别在一次重构里变成“顺便通用化”。

### ④ 选型（起草时已定）

Python 3 标准库优先；不引入外部向量数据库（保持可离线、零安装）。

### ⑤ 边界（起草时已定）

- **不写 ROSA 本体**（只读正文与设定）；
- 索引落本项目自己的目录。

### ⑥ 谁拍板

暮雨。

## 四、关于 ② 的落地物（起草时没想到、签收时才明确的）

**基线问题集是一份真实文件**，应当落在本仓库里（例如 `docs/baseline-questions.md`），
内容形如：问题原文 + 期望命中的段落（或“应当命中哪一类”）+ 当时的判定（过 / 不过）。

它有三个用处，都只有“落盘”才拿得到：

1. 改检索前后**可比**；
2. 新人接手时知道“什么样算查得准”；
3. 争论“要不要换方案”时有个客观起点。
