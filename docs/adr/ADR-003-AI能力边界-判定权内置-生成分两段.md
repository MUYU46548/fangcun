# ADR-003 · AI 能力边界：判定权内置，生成分两段，不做编排框架

- **状态**：提议（等你签收）
- **日期**：2026-10-29
- **决策者**：暮雨　**起草**：企鹅
- **触发**：暮雨「其实就一个问题：外包给外部 agent（更弱的控制力，对外依赖更大）还是内置（方寸产品的一部分）」
- **订正**：本 ADR 初稿第 2 条写「L2 仍关着」，**是错的**（见文末「订正」）。方寸自己出规划是**终局门槛**，
  不是被否的选项。ADR-001 第 3 条「不做 L2」应读作**一期限定**，我起草时写成了永久禁令。

---

## 上下文

**这轮争论一直把两件事当一件事，所以看起来像二选一。**

| 层 | 它解决什么 | 外包能拿到吗 | 内置要付什么 |
|---|---|---|---|
| **生成**（出内容：方案 / 拆解 / 归因） | **判断质量** | 能，且今天这套确实更强 | 维护面 + token + 质量不可判 |
| **判定**（什么算做完：判据 / 机检 / 收单 / 留痕 / 否决） | **控制力** | **拿不到** | 几乎为零 |

**三条实测，指向同一侧：**

1. **你缺的是判定权，不是判断质量。** 外面这套已经把 ADR / 契约 / 评审 / 业务界定一样样给你了，
   产物质量在；但 8 条 REV 里 5 条推翻前一个方向，46 条挂账里 11 件提了两遍以上还没落地。
   **换了一批更好的文档，问题一条没少** —— 因为没人能判"这条做完了没"。
2. **"内置要调模型"这笔账已经付过。** `fangcun-desktop/llm-config.json` 已在位
   （`baseUrl=https://tokenrhythm.studio/v1`，`model=deepseek-flash`），`ai-trace.jsonl` 有 5 条真调用。
   BYOK 通道不是新增成本，是既有资产。**"对外依赖"这件事因此不构成内置的额外代价。**
3. **唯一真实的增量成本，是编排框架的维护面** —— 而它恰好花在你最不缺的地方（你不缺流水线，你缺判据）。

**决定性的那条差别（不是"谁更强"，是"出事时谁能改"）：**

- 外部 agent 限流 / 政策变 → **你只能等**（今天这条消息本身就是实证）。
- 内置跑坏了 → **你能改代码**。
- 控制力的准确含义不是"我更懂它"，是「**失败模式可修 vs 不可修**」。

---

## 决策

**1. 判定权内置 —— 零外依赖、零 token，属于产品本体。**
　判据字段 / 机检 / 收单 / 留痕 / 否决键，五项全部本地实现（已有的 `shared/mismatch.ts` 是这一类，继续沿这条路走）。

**2. 生成分两段，不是一刀切。**

　- **终局：方寸自己出规划。（这是门槛，不是选项）**
　　你自己的 `docs/产品定义-方寸-20261027.md` 正式版门槛第 2 条写着：
　　「方寸基于这份定义 + 投入产出账，出**一份下一版规划**……含顺序、依赖、砍掉什么，且**你不用改就能拿去派活**」
　　（暮雨 2026-10-27 21:52 亲口「什么时候方寸能做好自身的规划，才算可以拿出去发正式版」）。
　- **一期：不做「L2 直出」。**
　　被否的是**形态**不是目标：一次调用直接吐方案 = 复述 + 不可审计，实测 4639 token / 59 秒 / 可用概率约 30%。
　　产品定义 §56-61 已经给了原因，不用再论证：直出的输入只有方寸自己写的卡和日志，
　　**「方寸规划自己」和「外部 agent 规划方寸」输入相同 —— 输出都只能是整理。**
　- **解禁判据（不是时间点，是输入条件）**：R1「白费可见」跑通 + 判据可机检。
　　在此之前它的规划拿不出新输入，做出来一定是复述 —— 那不是模型不行，是锅里没料。

**3. 编排不进本体，但「阶段 → 交付物 → 判据」落成模板（数据，不是代码）。**
　多角色多阶段流水线留在外面跑；方寸只持有**阶段定义与交付物判据**（可改的 md，不是引擎），
  据此派单（`tegula next` 已具备）与收单（机检）。换执行者 = 换插头，不动插座。

**4. 一条通用判据（防止第二次"规划按钮"）：**
　任何 AI 产出，必须满足其一才可作为"完成"依据 ——
　① 能在本地复算（字串 / 数量 / 格式 / 文件存在 / 测试结果）；
　② 你能一键否决。
　**模型的结论不算依据，模型提交的只是证据。**

## 考虑过但否掉的

| 方案 | 为什么不做 |
|---|---|
| **纯外包（全压外部 agent）** | 失败模式**不可修**：限流 / 政策 / 周期不透明，出事只能等。且它的产出仍是文档，判定权仍空 |
| **全内置编排（把外面那套搬进本体）** | 唯一增量成本（维护面）花在最不缺的地方；且框架进本体后换不起、降级不了 |
| **只加一个"派活"按钮，不改判定权** | 产出还是文字，回来还是靠你读 —— 那是**第二个规划按钮**，只是入口换了 |
| **现在就开 L2，而且要"直出"** | 不是目标错，是**形态**错：一次调用直接吐方案，输入只有自己写的卡和日志 → 只能复述；实测 4639 token / 59 秒 / 可用约 30% / 不可审计。要先有 R1 的白费账与判据，它才有料 |
| **把「不做 L2」读成永久禁令** | 这是我起草 ADR-001 时的措辞失准。用户 10-27 定的正式版门槛第 2 条明确要求方寸自己出规划 —— 禁令只能是一期口径 |

## 后果

**好的**
- 出事能自己改：限流、涨价、模型下线，方寸本体一行不用动。
- 判断第一次有宿主：判据在卡上、机检在本地、否决你按一下就落痕。
- 换供应商 = 换插件，不是重建。
- **通往"方寸自己出规划"的路没被堵死，反而第一次有了入口**：规划要能吃证据，先得有证据可产。

**代价（必须写）**
- **一期方寸还是不会自己出规划。** 这是顺序代价，不是取舍放弃 —— 区别在"什么时候"而非"要不要"。
- 判据（决策 1、4）先建不是因为它比生成重要，是因为**没有它，生成出来的东西不可验收** ——
  先做生成 = 第二个规划按钮。
- 若哪天判据写不出来，那不是"该上编排了"，是**这个交付物本身还不够清楚** —— 会被暴露出来，而不是被工作流盖住。
- 阶段模板是数据不是引擎，所以它**不会自动往下跑**；每一步仍要有人（你或 agent）真的推一下。

## 与 ADR-001 的关系

ADR-001 仍是方案唯一入口。本 ADR 补它两处：
1. 它第 3 条里"存、比、拦"的**「拦」**——它自己承认"还没有任何设计"（见其「这份 ADR 自己承认的问题」第 2 条）。
   本 ADR 决策 1 与 4 就是那个「拦」的定义。
2. 它第 3 条「不做 L2」的**口径**——应读作一期限定，不是永久禁令（见下「订正」）。

## 订正（2026-10-29，同日自纠）

**我起草 ADR-001 时写「不做 L2（不直接生成方案）」，这个措辞是失准的，会把人带进两条错路。**

- 事实：你 10-27 21:52 定的正式版门槛第 2 条，明确要求**方寸自己出一份下一版规划**。
  所以"方寸自己生成方案"从来是**终局门槛**，不是可选项。
- 被否的是**形态**（一次调用直出、复述、不可审计），不是目标。我把"那次实现失败"记成了"方向被否"。
- 这是今天第三次同类错误（前两次：把"担心搞成自研 agent"升格成红线、拿别人的判断当你的拍板）——
  共同形态是**把一次实测的失败，升格成一条方向禁令**。记在这里防第四次。

**写清楚的界线**：ADR-001「不做 L2」= **一期不做「L2 直出」**；终局要做 L2，条件是输入先有料（R1 白费账 + 判据）。

## 待你签收

签了这一份，就定了往后所有 AI 相关施工的分界：
- **判据 / 机检 / 收单 / 留痕 / 否决 → 内置，现在就可以做**（这是生成的前提，不是替代品）
- **生成 → 终局归方寸（门槛第 2 条）；一期先由外部 agent 交单**，方寸只认交付物与判据
- **编排 → 不进本体**，只留阶段模板与判据
- **L2 直出 → 一期不开**；解禁判据 = R1 跑通 + 判据可机检（不是时间点）
