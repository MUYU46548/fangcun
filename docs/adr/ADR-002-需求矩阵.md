## 上下文

**这次要解决的不是"再做一个打分表"，是让判断能累积、且不再丢。**

| 事实 | 出处 |
|---|---|
| 10-24 的 RICE 打分表被自己否掉：奖励"清理"、惩罚"证明" | `docs/0.5.0-范围裁剪与里程碑` §5.2 |
| 10-25 花钱做出原型，次日需求被改写成"手动排序小玩具"，RICE 断线 | `docs/小样-RICE决策矩阵-20261025/README.md` |
| 10-24 三连裁决：①独立工具全否（必须内嵌页签）②AI 通道否决（方寸运行时零 AI，初分由 agent 顺手写入）③页签零外部连接 | 打分口径 spec 开头 |
| 格式闸实勘：agent 经 MCP 的写工具**只有任务卡四件**，决策卡/池文件**根本没有通道** | 格式闸 §一 |
| registry 是**项目级**注册表，塞条目级分数是错配，且要动两端解析器 | 格式闸 §一 / §五 |
| `addDecision` 自带幂等（同内容+同日期）；`备注` 多行续行现成 | `desktop/src/main/data/decisions.ts` |
| 双端兼容是既有纪律：decisions.md 由 TS 与 Python 两腿同文件读写 | decisions.ts 头注释 |

**约束**（不能违反的）：
1. 契约 REV-008「有对象，没门禁」：**不打分决定优先级、不设门、不阻挡**；每个数字自带「它证明不了什么」。
2. 零依赖红线；页签**零网络**。
3. LLM BYOK 三边界：方寸运行时不做 AI 推断；初分由外部 agent 经 MCP 写入。
4. 写别人的仓库？不做；池文件在**方寸自己的数据目录**。

## 决策

**1. 池宿主 = `task-data/rice-pool.md`，节式格式（与 decisions.md 同款）。**
　四类异源条目（任务卡 / 待办 / 想法 / 外部清单）必须统一宿主；独立文件零侵入
　（不动 decisions / ideas / registry 的接口）。

**2. 池里只存四个原始分，总分不落盘。**
　`RICE = R × I × C ÷ E` 由页签端现算。手改任一分项，总分与等级当场重算，
　永远不会出现"总分与分项打架"。

**3. 取值域硬校验（schema §3.2），非法条目拒该条不拒整批。**
　- `I ∈ {0.25, 0.5, 1, 2, 3}`（省手工量）
　- `C ∈ {0.95, 0.85, 0.7, 0.6}`（信心，**由证据等级决定**：亲口要 / 实测踩过 / agent 推断 / 纯直觉）
　- `E天` 正整数（进公式）；`E元` 旁注（不进公式，可空）
　- `R` 非负（每周真实频次；同时是散点气泡大小）
　- 来源 `type:id`，`type ∈ task/idea/todo/external`；引用 task/idea/todo 时**校验存在性**

**4. 幂等 upsert。** 同 eid 再灌：覆盖分数 / 备注 / 打分，**保留已存在的 `拍板:` 与 `决策id:`**，
　池条目数不变。这是格式闸验收线，也是"agent 顺手写入会有重复回显"的必要前提。

**5. 写口只有两个 MCP 工具 + 一个只读列表（入口 A，桌面端）。**
　- `rice_pool_upsert`：初分写入（幂等 / 逐条校验 / 来源存在性）
　- `decision_record`：包装 `addDecision` 落 decisions.md，成功后回填池条目 `拍板:` / `决策id:`
　- `rice_pool_list`：只读（含现算分数与等级）
　- Python 侧只做**解析 / 渲染 + 只读 CLI**（`tegula rice [--json] [--level]`），**不开第二个写口** ——
　　两套写路径会绕过同一套审计（10-24 流转链病灶的形态）。

**6. 拍板只落 decisions.md，registry 不动。**
　RICE 分数与依据进决策卡 `备注` 多行字段，`Decision` 接口**零扩展**。
　CUT = 决策状态「已撤销」，池里留痕不删。
　**拍板是用户动作**：按钮在页签上，agent 只供初分不代拍。

**7. 等级是池内相对位置，不是绝对分数线。**
　`P0 = 前 20%`、`P1 = 到中位`、其余 `P2`；同分共享档位；已拍板 CUT 恒 CUT。
　原型那套 `P0≥2000 / P1≥500 / P2≥120` **作废**（方寸池量级小两个数量级）。
　容量护栏 = **月预算（元）**，落在池文件头部（放 prefs 里换 origin 就没了）；
　预算未设置时**明说未设置**，不许说成 0%。

**8. 页签 = 项目页第 7 种摆法（`rice`），零网络。**
　散点（横轴成本天数 / 纵轴 RICE / 气泡大小 = 使用频次）+ 表格（手改即时重算）+ 拍板按钮。
　入口文案与空态明说「池里还没有条目，灌分走 `rice_pool_upsert`」，并常驻展示池文件路径。

## 考虑过但否掉的

| 方案 | 为什么不做 |
|---|---|
| **独立工具 / 独立页面** | 暮雨 10-24 三连裁决第一句：独立工具全否，必须内嵌方寸页签 |
| **页签内置 AI 打分 / 联网** | 第二、三句裁决：方寸运行时零 AI、页签零外部连接；初分由外部 agent 顺手写入 |
| **总分落盘** | 手改单项后必须同步总分，否则出现"总分与分项打架"（格式闸定稿否掉） |
| **registry 加优先级字段** | registry 是项目级注册表，条目级分数塞进去是错配；且要动两端 parseRegistry，不值 |
| **沿用原型绝对分数线** | 池量级小两个数量级，绝对阈值会把所有条目压进同一档；先按分布定位，第一轮真数据后再重定 |
| **Python 也开写口** | 第二条写路径 = 绕过同一套乐观锁与审计；格式闸只给入口 A 开写 |
| **手搓直改 rice-pool.md** | fangcun-bridge 边界纪律同款：绕过原子写与审计，就是 10-24 流转链病灶复发 |

## 后果

**好的：**
- 判断第一次有了**可累积的宿主**：分数、证据、拍板、决策 id 在同一张卡上，跨会话不丢。
- 池文件是人可读可手改的 Markdown；改坏了 parser 宽容跳过并把坏值原文留在 `raw` 里，写回不静默清空。
- 两条腿（TS / Python）逐字节对账：Python 渲染的文件交给 TS 解析再渲染，结果与原文一致。
- 原有三处（decisions / ideas / registry）接口一行没改。

**代价 / 局限：**
- 页签不提供"新建条目"表单：初分必须来自 agent（MCP）或手改文件 —— 这是 R6「不要求用户写」的代价，
  但空池时用户只能等 agent 灌分（空态已明说路径）。
- 等级随池子变化，**同一个条目在不同批次里可能换档**；这是"相对位置"的固有属性，页面已写明。
- `E元` 只是旁注，不参与排序；月预算只约束 P0 花费，不是硬性拦截（REV-008：不设门）。
- 证据等级与 C 的对应关系只做**警告**不做拒绝：手改 `C` 与证据不一致时收下并提示，
  因为"用户有权改分"优先于"口径纯洁"。

## 防丢措施（这一节是这份 ADR 存在的理由）

1. **宿主文件在数据目录**：`task-data/rice-pool.md`；页面顶部直接显示绝对路径。
2. **口径进代码而非对话**：`desktop/src/shared/rice.ts`（TS）+ `tegula/core.py`（Python）两腿同规则，
   两端取值域 / 证据映射由 `check-rice.py` **逐字对账**。
3. **回归钉死验收线**：`scripts/test/e2e-rice.cjs` 88 条（含幂等实证：同 eid 连灌两遍条目数不变；
   拍板后回填决策 id；再灌分保留拍板；MCP 三件直调 handler 真跑）· `scripts/test/check-rice.py` 33 条
   （含双腿逐字节对账）。
4. **本 ADR + 开发日志**：设计判断、被否方案、局限全部落盘，下一轮会话读它就能接着改。
5. **原型归档**：`docs/小样-RICE决策矩阵-20261025/`（结构与口径来源，演示数据不作数）。
