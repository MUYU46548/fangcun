# ADR-001 · 方寸的定位与一期范围

- **状态**：提议（等你签收）
- **日期**：2026-10-27
- **决策者**：暮雨　**起草**：企鹅
- **取代**：REV-004（「全周期管理平台」列为不受理项）

> ⚠ 严格说 ADR 一条只记一个决策。这份装四条，因为**它们互相依存，拆开就失去上下文**——
> 单独看第 2 条"抄不自研"会不知道抄来干什么。这是对格式的**一处故意违反**，记在这里。

## 上下文

**为什么必须现在定。** 以下全是实测，不是感觉：

| 事实 | 数据 |
|---|---|
| 方寸工程投入不小 | 30 天 175 次提交、48 个 e2e、七个守卫、173 张卡 |
| 但真正被用的只有一个 | 暮雨：「用的最多的全是日志」——而且是"只有这个东西能用" |
| 卡完成率不可信 | 173 张卡里 **62%（108 张）没有可判定的验收标准**；137 张的「验收」字段填的是人名 |
| 三个主力都停在"能用"之前 | 绒花墨坊 263 次提交还没试跑成；司天 187 次 M1 未开始；方寸 175 次只用日志 |
| 方向反复 | 8 条 REV 里 **5 条是推翻前一个方向**（REV-004 收 REV-003，REV-008 再收 REV-004） |
| 一晚拿不出方案 | 2026-10-27 20:26→22:05，**8 份文档，形状全不同**，被否的 7 条散在对话里 |

**约束（不能违反的）：**
1. 契约 ③：不写别人仓库 / 不做重型表单与流程引擎 / LLM 只能 BYOK 且产出只落待审批
2. **我不往里写东西**。93 张待办没人动、74 张卡是 10-15 一天批量导入后沉底的 —— 要求我生产的都没活下来
3. 桌面为主（Windows 11），Web/CLI 只作通道

**核心症状一句**：不是缺方案，是**没有一个对象承载"当前判断"** ——
所以每轮都在重新发明形状，被否的条目下一轮就丢。

---

## 决策

**1. 定位改为「项目全周期管理」（REV-008），一期只做前两段：定义、规划。**
　七段 = 定义 / 规划 / 执行 / 验收 / 发布 / 运维 / 复盘；另五段留对象位，不施工。

**2. 主轴：抄，不自研。格式一条都不发明。**

| 要的东西 | 抄谁 |
|---|---|
| 当前方案 / 判断累积 | **ADR**（状态 / 上下文 / 决定 / 考虑过但被否的 + 为什么） |
| 需求 | **User Story + Acceptance Criteria** |
| 「什么算做完」 | **Definition of Done**（清单，不是人名） |
| 规划 | **Milestone / Phase plan** |

**3. 外部 agent 做脑，方寸做「存、比、拦」。** 用户只点头或否。
　LLM 深度：L0 为主（零 LLM 的容器与检查）+ L1 少量（只搬事实，不发判断）+ **不做 L2（不直接生成方案）**。

**4. 方寸唯一自研的部分：跨项目聚合 + 与本仓已有的卡 / 日志 / 契约 / 决策连上。**
　除此之外的一切，凡是现成有的，照抄。

## 后果

**变好的**
- 有地方累积判断了：下一轮读 ADR 就能接着改，不用重读 6 万字对话
- 死路有档案：**ADR 天生带「考虑过的其他方案」这一节**，被否的 7 条正好装进去；
  下次谁再提 SDD，能看到它是哪天被否、为什么
- 62% 没验收标准这个洞，有了明确修法（DoD，一份清单而不是一个人名）
- 不再从零设计格式：抄，省掉的就是今晚烧掉的那十几轮

**变差的（必须写）**
- **方寸要新增一类对象**，数据模型要动，不是加个视图就完
- **一期只做两段，剩下五段挂着**——视觉上就是"没做完"，会一直有"要不要补"的冲动
- **格式被 ADR 绑住**：以后 ADR 装不下要改格式，那就得迁移历史 ADR
- **抄不等于对**：ADR 是给"单个技术决策"设计的，方寸要装"多项目 + 跨阶段"，很可能装不进

## 当前状态与下一步

> **写这份时发现的问题**：标准 ADR 里**没有「下一步」这一节** —— 它是决策档案，不是活方案。
> 而你要的"下一轮接着干"必须有这一节。**这是抄格式遇到的第一个不匹配，我先在这里补上，不另开格式。**

- **现状**：文字阶段，零行代码改动。契约已改（REV-008），其余全是文档。
- **下一步（等你签收本 ADR 才动）**：
  1. 你签收 → 这份成为"当前方案"的唯一定稿，旧 5 份按文末附件关系处理
  2. 第一件动代码的事：**给方寸自己写一份 ADR**，跑通「读 → 改增量 → 存回」这条链
  3. 判据：**下一轮会话读这份文件就能接着干，不用重读今晚这 6 万字对话**。做不到就砍这条路。
- **明确不做的**：七段里另五段、任何新视图、任何"一键生成"按钮。

## 这份 ADR 自己承认的问题

1. **"抄不自研"是你的判断，我认，但没有验证过。** ADR 装"多项目 + 跨阶段"到底行不行，没人试过。
2. **第 3 条「方寸做存比拦」里，"拦"还没有任何设计。** 怎么写、拦在哪个环节、误拦怎么办——全是空的。
3. **四条决策捆在一份里，如果第 2 条（抄）不对，前 3 条会跟着倒。** 这是捆绑风险。
4. **这份仍然是文字。** 你的判断是"大概率几乎没用"——如果这份也没用，那说明问题不在文档组织方式，
   而在**我没有能力替你判断方寸该长什么样**，该换人（换 agent/换思路）而不是换格式。
