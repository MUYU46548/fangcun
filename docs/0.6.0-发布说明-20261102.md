## 二、破坏性变更（升级前必读）

### 1. MCP `set_log_status` 只接受 `running` / `idle`

`request_close` / `complete` / `archive` 一律被拒，并回一句“用 `move_status` 把任务移到待验收”。

**影响**：如果你的 agent 脚本里调过 `set_log_status(action='request_close')`，升级后会收到错误。
**处理**：改成 `move_status(task_id, '待验收')`。

### 2. 日志的 `agent_done` 字段被移除

历史文件里的 `agent_done` 读取时忽略，下次写回自然消失。**不需要手工清理**。

### 3. 按钮尺寸变化（视觉）

大档按钮 32px → 34px，圆角 8px → 10px。布局高度会多 2px。
**影响**：如果某处依赖精确 32px 的画布高度，会看到 2px 偏移。

### 4. 新增数据文件（旧版不认识，但不影响）

| 文件 | 用途 |
|---|---|
| `llm-channels.json`（数据根） | BYOK 备用通道 |
| `task-data/plans/_drafts/*.md` | 计划草案（状态恒“待裁决”） |
| `task-data/project-order.json` | 项目优先级手动排序 |

回滚到 0.5.x 时这些文件**留在原地即可**，旧版忽略它们，不会报错。

## 三、升级指引

方寸的数据层是纯文件 + frontmatter，**升级不做 schema 迁移**。

1. 关闭方寸（托盘图标右键退出，不是关窗口）。
2. 先做一份备份：设置 → 数据 → 立即备份（或用 `tegula backup`）。
3. 运行 `Fangcun-Setup.0.6.0.exe`，覆盖安装。
4. 启动，检查三项：
   - 项目页能看到第 8 种摆法“作战计划”
   - 设置 → Agent 能看到“备用通道”
   - 随便点一张任务卡，详情里有“计划 vs 实际”两栏
5. 打开设置 → 关于，确认版本号是 0.6.0。

**耗时**：安装约 30 秒，上述检查约 1 分钟。

## 四、回滚指引

演练脚本：`node scripts/test/drill-060-upgrade.cjs`（**全程在临时目录，不碰真实数据**）

实测结果（2026-11-02）：

```
基线：卡 241 / 决策 47 / md 文件 242
升级后使用：卡 242（新增 1 张）
回滚：卡 241 / 决策 47 / md 文件 242  ← 逐项一致
整树指纹：与快照逐字节相同
耗时：快照 406ms · 升级+使用 53ms · 回滚 505ms
```

步骤：

1. 关闭方寸。
2. 找回升级前那份备份（`backups/` 目录里按时间找，或你手动导出的包）。
3. 用恢复脚本还原 `task-data/` 与 `registry.yaml`：
   ```
   node scripts/test/drill-restore.cjs --zip <你的备份包>
   ```
   （该脚本默认把结果落到**临时目录**；要在真实目录里恢复，按它打印的提示手工搬。）
4. 卸载 0.6.0，安装 `Fangcun-Setup.0.5.7.exe`。
5. 启动后核对：卡数、决策数、日志数和备份点一致。

**注意**：回滚会丢掉升级后新建的卡与写入的日志。回滚前先把它们导出或抄走。

## 五、这份说明没覆盖的

- **没做真人界面点击验证**：`e2e-renderer` 需要桌面会话，本轮未跑（`e2e-renderer-web` 1088/0 是无头浏览器，验不了真 IPC）。

- **AI 起草的产出没有人工评估**：首单跑了 5 张阶段卡，模型和成本都记了（11,046 tokens），但“这份规划好不好”没有客观判据 —— 这也是它只落“待裁决”的原因。
