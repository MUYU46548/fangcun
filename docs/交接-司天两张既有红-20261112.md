## 一、`test_69`：f1 断言过时（十几分钟）

**文件**：`scripts/tests/cases/test_69_terrain_raster_shared.py`

### 现在的断言（第 121–126 行附近）

```python
# ★ 平滑档（反“拼豆”）：① 画布是**子格分辨率**（比世界尺寸小，靠绘制端插值放大）；
ck('f1 ★ 平滑档画布为子格分辨率（边长远小于世界尺寸）',
   smL.canvas.width > 0 && smL.canvas.width < smL.w,
   ...)
```

### 为什么必然红

`9b06865` 把底档烘焙改成**固定 4096 宽**（后来 `8cba1b4c` 又改成“按缩放定宽度”）。
无论哪一版，**`canvas.width` 都不再必然小于世界尺寸** —— 世界宽可能只有 777，画布却有 1152/4096。
所以 `canvas.width < smL.w` 这个判据在固定宽度策略下**恒不成立**，与代码好坏无关。

### 怎么改（三选一，建议 A）

**A（建议）—— 判据换成“画布宽度只由缩放档决定”，这才是现行意图**

```python
# 2026-11-12 修：固定 4096 / 按缩放定宽之后，「画布 < 世界尺寸」不再成立也不是 bug。
# 现行意图是：**画布宽度由缩放档决定，不随格距膨胀**（8cba1b4c 的代价账）。
ck('f1 ★ 平滑档画布宽度只由缩放档决定（不随格距膨胀）',
   smL.canvas.width in (777, 1152, 2053, 4096),   # 按 8cba1b4c 的三列账取真实档位
   {w: smL.canvas.width, 世界宽: smL.w})
```

> ⚠ **别照抄我给的档位数字**：从 `8cba1b4c` 的代价账表里取**当前实现真实产出的档位**。
> 我这份是只读看到的 777 / 1152 / 2053 / 4096 四个值，你的实现可能已经改了。

**B —— 断言“子格分辨率”只管该管的那一档**
只有当宽度策略是“世界宽×4/格距”时才成立。把这条断言限定在那个档位下跑，
固定/按缩放档位跳过（用 `pytest.mark.skipif` 或直接分两支）。

**C —— 删掉这条断言**
不推荐：它原本防的是“画布被撑成全图导致每帧爆内存”，这个风险还在，只是判据要换形状。


判据：**全绿**，且新断言在“把宽度改回固定 4096”时**会红**（反例自证一次，否则等于没验）。

## 二、`test_110`：用例没铺省份（半天）

**文件**：`scripts/tests/cases/test_110_river_discoverability.py`

### 现在的流程（第 218–223 行附近）

```python
btn = _ev(cdp, JS_BUTTON, '“更多”里的按轮廓生成地形')
if not btn:
    fails.append('🔴 “更多”里找不到 `basemap-synthesize-terrain` 按钮')
```

找的选择器是 `[data-testid="basemap-synthesize-terrain"]`（第 21 行注释里写明了）。

### 为什么必然红

卡上说得很清楚：**「用例没铺省份，判据与隐藏条件对不上」**。
`basemap-synthesize-terrain` 的显示条件里含 `!baseMapHasHeightmap` 之类的**
前置状态**，用例没把状态铺到那个条件成立，按钮就不渲染 —— 不是按钮坏了。

> 第 11 行注释写着：第一版显示条件里含 `!baseMapHasHeightmap`，说明这个坑之前就出现过一次。
> **同一个坑第二次出现，说明它缺的不是修法，是“用例自己先断言前置条件”这一步。**

### 怎么改（建议 A）

**A（建议）—— 用例先铺前置状态，再断言按钮**

在找按钮**之前**加一段 fixture 准备：

```python
# 2026-11-12 修：这个按钮有显示前置条件（第一版是 !baseMapHasHeightmap，现在可能更多）。
# 用例必须**先把前置铺到成立**，否则断言的是“条件不满足时按钮不存在”——那不是 bug。
_prepare_state_for_synthesize(cdp)     # ← 具体要做哪几件事，见下
ck('前置已铺（按钮应当出现）', _synthesize_precondition_holds(cdp))
btn = _ev(cdp, JS_BUTTON, '“更多”里的按轮廓生成地形')
```

`_prepare_state_for_synthesize` 要做的最小集合（按第 11 行注释推导，**需司天侧确认**）：
1. 有底图（省份多边形已铺）；
2. **没有** heightmap（否则 `!baseMapHasHeightmap` 不成立）；
3. 切到“更多”面板。

**B —— 反过来断言“条件不满足时不显示”**
如果第二个隐藏条件（有一个 heightmap）是**有意的产品行为**，那这张卡该改写成
「按钮在 X 条件下隐藏是设计」而不是“找不到按钮是 bug”。这条路**要先拍板**。

```bash

```

判据：全绿；且**故意不铺省份时该条会红**（证明它测的是按钮，不是空转）。
