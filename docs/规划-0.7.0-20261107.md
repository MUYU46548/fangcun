## 一句话

**0.7.0 只做一件事：让"token 花在哪、换来什么"第一次能算出来** —— 其余全部让路。

## 为什么是这一件（三条事实逼出来的）

1. 账上 **99.3% 的 token 是 cache_read**：现在的"花销"数字量的是上下文长度，不是劳动量。
2. **93% 的 token 归不到任何卡**（217 条里只有 4 条带 `card=`）：不修，投入产出永远是分母不清的平均数。
3. 方寸自己的调用只占 **0.0024%**、失败率 **50%**（plan-draft 3 挂 2、archGenerate 2 挂 2，全死在"不是 JSON"）：
   它的价值不在省钱，在**别再白跑**。

> 判据一句话（照 P5 的口径要求）：**0.7.0 交付后，能回答"过去 N 天花了多少新 token、产出几件真被用起来的"，
> 且每个数字旁边写着"它证明不了什么"。**

## 顺序与依赖

```
W3（独立，先做，半天）──┐
                        ├─→ W4（自检报告，引用 W1/W2 的数字）
W1 ──→ W2 ──────────────┘
W5（独立，随手做；它修的是"账本对不上卡"的另一半）
```

先 W3 的理由：它最小、最疼（50% 失败率）、且**与报表无关**，做完立刻少烧两次 1.8 万字符。
W1 → W2 串行，因为归因闸要用 W1 的口径去打标签。
W4 最后：它要引用 W1/W2 的产出，早了只能引用假数字。

## 第一批可派活（3 张，AC 直接抄进卡）

1. **W3 结构化输出修复环**（半天）
   AC：① 解析失败时先抽 `{...}`/`[...]` 片段重试一次；② 两次都失败 → 报错分型写清 `no_content` / `not_json` / `truncated`；
   ③ trace 记 `retried`；④ 反例：喂带前后缀解释的响应能救回，喂截断的仍失败且文案指出截断。
2. **W1 报表口径**（半天）
   AC：① `新输入 = prompt − cache_read`，`completion` 单列，`total` 降副列；② 缺 token 字段的记录**不参与**新输入统计（空着，不补 0）；
   ③ 每个指标带 `proves` 一句话；④ 反例：全 cache 的记录 → 新输入为 0 而不是等于 total。
3. **W2 归因闸**（半天）
   AC：① 外部上报无 `card=` → 落 `(未归因)` 并照常入账；② 报表首屏出"未归因占 X%"；③ 按卡汇总能出 top N；
   ④ 反例：把 `(未归因)` 混进 top N 单卡排行必须红。

> W4、W5 先不派：W4 要等 W1/W2 的产出，W5 是"随手做"的维护活（到点标记），不占排期。
