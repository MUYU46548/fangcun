## 一句话

两份调研都指向同一个真缺口：**"怎么反馈给施工方"没做完**。
方寸此前的"出单"只产出一段**提示词**，谁去把它变成卡没人管 —— 链断在最后一步。
本轮把这一公里打通：**已批准的答卷 → 真任务卡**；**想法 → 真任务卡**（不再只进待办这条死支线）。

## 故意不抄的三条（并说明为什么）

1. **条件显隐（上一题答案决定下一题）**：方寸的卷是 agent 写死的 md，动态显隐要求"出题也是程序"，
   等于把 `questionnaire:create` 这个禁区打开（暮雨原话：问卷全是 agent 写的）。
2. **公开投票 / 众填门户**：productboard 自曝失败史；单用户场景纯属加噪声。
3. **重表单引擎 / 审批流**：契约"重型表单/流程引擎不受理"，且 REV-008 明确"有对象，没门禁"。

## 仍欠的（下一步，按价值排）

1. **`expected_output` 进 schema**：现在只有正文段落，看板/派活读不到它。
   要动 `TASK_FIELD_SPECS` + `FM_ORDER` + Python 侧（一次双侧契约改动，需单独一个窗口）。
2. **卡的完成能回写问卷**：现在问卷 → 卡是单向的。卡完成/驳回后，问卷那条答案的"验收"应该能自动看到结果
   （对应 `/converge` 的另一半）。
3. **卷面体检的 EARS 软检查**：验收线像不像可判定句（"当…应…"）。做成提示不判红 —— 误判成本高。
4. **批大小自动拆**：现在只报"超 6 题"，不拆。拆批要 agent 做（同"不许替 agent 改题"）。
