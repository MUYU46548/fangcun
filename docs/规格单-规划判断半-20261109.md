# 规格单 · 规划能力的判断半（2026-11-09）

> 来源：暮雨 2026-11-09 的方案 `方寸-问卷系统强化-详细方案-20261109.md`。
> 本文是**本地 agent 的规格单**（方案里写明“出单权在本地”）。不新开跑道、不改立项契约、
> 不动其他项目；只把“判断半”接进方寸已有的写路径。
>
> 一句话：**把问卷从“一次性问答”变成“规划流水线里的硬关卡” —— 判断半进方寸，执行半留给外部 agent。**

## 0 口径（先钉死，防跑偏）

1. **“一半”指判断半**：问对问题、定取舍、给验收线。执行半（写代码、出施工）不搬进方寸。
2. **零新建表**：只新增 1 份 md 台账 `task-data/question-bank.md`（题库），不引数据库、不改状态机。
3. **闸在写路径里判，不写在提示词里**。2026-11-09 前的实测结论就是“AI 不问不读”，
   提示词约束过不了这一关；只有“写不进去”才算闸。
4. **不替暮雨答**：所有答案仍由他在问卷页点；agent 只能出卷、不能批准。

## 1 现状：已经有的零件（别重做）

| 能力 | 落点 | 状态 |

| 出卷通道（agent 侧） | `qn_propose` → `createDeck` + `desktop/src/shared/qnDeckSpec.ts` 机检（选项代价 / 验收线 / 题号） | 有（11-08） |

## 2 三个缺口（都有现场证据）

### 2.1 强制闸不存在

- `planDraftInput.ts:66-70` 组装规划输入时**只装 task 卡**：没有产品定义、没有决策卡、没有问卷。
  也就是说方寸起草计划时，**连 47 条旧拍板都看不见**，更不会先问。
- `proposeStage()` 只校验“技术方案 / 照抄点 / 判据”三块格式，**不校验有没有澄清问卷**。
- `deckToCards()` 有“没批准 / 有反问就拒”的闸，但那是“答案 → 卡”的闸，
  不是“提案 → 必须先问”的闸。
- 派工单 `desktop/src/shared/arsenal.ts:66` 的验收段**故意留空**（防锚定），
  所以“答案直连施工单”在派工单这一层是断的。

### 2.2 题库不存在

- 答案按卷存在 `task-data/questionnaires/<卷>.answers.json`；**卷删了，记录就没了**。
  （现在 `questionnaires/` 已空，4 份早期卷在 `.trash/questionnaires-20261108-legacy/`。）
- `createDeck()` 不查重：同一道题换个卷名可以再问一遍，“同一道题被问第二次 = bug”守不住。
- `QAnswer.kind` 只有 `pick / skip / reject / askback / amend / void`，**没有“你自判”**，
  方案要求的黑名单从第一天起就缺一类来源。
- `approveDeck()` 建决策卡时**不写 `项目`**（`questionnaires.ts:429-435`）。
  `addDecision` 本身支持 `项目`，但这里没传 —— 后果是问卷答案落成的是**全局决策**，
  而 `contextPack.ts:157-159` 会把“项目为空”当全局规矩发给每个项目。

### 2.3 答案直连执行只通了一半

- 通：`deckToCards()` 把【验收线】原文搬进卡（`questionnaires.ts:856-857`）。
- 断：`plan_draft`、`stage_plan_propose`、派工单**都不继承已批准答案的验收线**；
  决策卡与问卷之间只有 `出处` 字符串（`问卷 <卷> · <题号>`），没有结构化关联。
- 方案要的“任一已落档答案，在后续相关施工单里找不到对应验收项 = 直连断了”，
  现在没有机器能判这一条。

## 3 三构件设计

### 3.1 强制闸（硬锁）

**两个时点，别混：**

| 时点 | 判什么 | 不过怎么办 |
|---|---|---|
| **出厂**（提案） | `plan_draft` / `stage_plan_propose` 必须带 `deck`（或 `clarify: none` + 理由） | `ok:false`，**零写入** |
| **进队列**（施工） | 卡 / 阶段要“可派”，必须有 `澄清: <卷> 已批准` 且无未答活题 / 无反问 | 落「草稿」不进「待办」；派工按钮禁用并给原因 |

- **零问题 = 闸不开**：卷里全是否决 / 作废 / 黑名单，视同“没有澄清” → 拒。
- **状态表达不新增状态**：阶段块加 `- 澄清: <卷> / 缺卷`；卡 frontmatter 加 `澄清: <卷>`。
  缺卷的提案落「草稿」（现有状态），不落「待裁决」。
- **必读闸**：`plan_draft` 输入注入“本项目有效决策 + 已落档验收线”；
  `intake_task`（`services/intake.ts#checkIntake`）对声明了 `拍板: D-xxx` 的卡
  **自动追加一条判据**：交付物里必须出现该 `D-xxx`（没提或唱反调 = 没读，闸不开）。
  这是“用输出引用旧拍板当读没读”的机器版。

**为什么必须 server-side**：`plan_draft` / `stage_plan_propose` / `qn_propose` 都是 MCP 写入口，
闸放在这里，agent 绕不过；放提示词里等于没放（已实测）。

### 3.2 题库双源

**落点**：`task-data/question-bank.md`（md 台账，一条一题；不是表）。

```
## Q-0001 <指纹>
- 问题: 当 X 时，系统应当 Y 吗？
- 指纹: <归一化后的题干哈希/文本>
- 首问: 2026-11-09 · 卷 <deck> · 题 S3
- 状态: 待答 | 已答 | 否决 | 作废 | 你自判
- 答案: <选择 / 原话>
- 出处: <证据来源>
```

- **人工源**：反问（`askback`）→ 待答；否决（`reject`）→ 黑名单。
- **自动源**：`approveDeck` / `voidAnswer` 回写状态；新草案与有效决策做**确定性覆盖检查**
  （见下），冲突/未回应自动生成待答题。
- **查重**：`createDeck()` 先算每题指纹（去空白标点、统一大小写、去题号），
  命中「待答 / 已答 / 否决 / 你自判」→ 拒收；命中「作废」→ 允许重问（需求变过）。
- **你自判**：`QAnswer.kind` 增 `self`；不进决策、进黑名单；界面加第五个动作。
- **读口**：`qn_list` 返回“本项目已问过 N 题 / 黑名单 M 条 / 待答 K 题”，
  让 agent 出卷前先看，而不是在聊天里重问一遍。

**自动源 v1 只做确定性覆盖，不做语义判断**：

- 对新草案里的每张阶段卡 / 每个提案，按“项目 + 关键词命中”挑出相关有效决策；
- 草案没引用它、也没写“本条不涉旧拍板” → 生成一道待答题：
  “草案提到 X，但没提 D-yyy；仍按 D-yyy 吗？”；
- **不判断谁对谁错**（那要 LLM，留给后续 BYOK 可选增强）。

### 3.3 答案直连执行

- 新增派生函数 `effectiveAcceptances(project)`：
  遍历「已批准 + 未作废 + 无反问」的卷，抽 `{deck, qid, 选择, 验收线}`。
  **派生，不落表**；卷作废/答案被推翻后自动消失。
- 注入三处：
  1. `plan_draft` 提示词的「旧拍板」段（含验收线），并要求阶段卡的 what 回应它；
  2. `stage_plan_propose` 落卡时自动写 `- 相关旧拍板: D-xxx, D-yyy`；
  3. 派工单新增第 7 节「已落档的验收（来自问卷）」—— **追加，不覆盖**第 5 节人工验收，
     保住 `arsenal.ts` 防锚定的原设计。
- **修 `approveDeck` 的 `项目` 字段**：从卷名/正文解析出项目再传给 `addDecision`，
  否则直连会串项目（上面 2.2 最后一条）。
- 判据：任一已落档验收线，在后续相关卡 / 派工单里必须出现；不出现 = 直连断了。

## 4 施工顺序（每步独立可验收）

| 步 | 做什么 | 判据 / 反例 | 估 |
|---|---|---|---|
| **S0** | 修洞：`approveDeck` 写 `项目`；`plan_draft` 注入有效决策（只读） | `e2e-plan-draft` 断言提示词含决策原文；反例：问卷决策不再进“全局” | 0.5 天 |
| **S1** | 硬闸：`plan_draft` / `stage_plan_propose` 必须带卷；没带零写入；阶段块显示 `- 澄清:` | 反例：不带卷调用 → 文件逐字节不变；全否决的卷 → 仍拒 | 1 天 |
| **S2** | 题库：`question-bank.md` + 指纹 + `createDeck` 查重 + `self` 类型 | 反例：同一题换卷名再出 → 拒；卷删了黑名单仍在 | 1 天 |
| **S3** | 直连：`effectiveAcceptances` + 派工单第 7 节 + `intake_task` 拍板判据 | 反例：已批准验收线没进派工单 → 红；作废卷的线不再出现 | 1 天 |
| **S4** | 首战：拿方寸自己“下一轮做什么”跑一轮完整流水线 | 只有一条：昨晚骂过的问题，它能不能先问出来 | 0.5 天 |

**每步都要反例自证**（注入 → 精确变红 → 还原），沿用本仓 e2e 惯例；
新套建议 `e2e-qn-gate.cjs`、`e2e-qn-bank.cjs`、`e2e-qn-direct.cjs`。

## 5 本规格单不做

- 不自研 agent、不引依赖、不加新状态、不新建表（题库是 md，不是表）。
- 不替暮雨答题 / 不自动批准 / 不写别人仓库。
- v1 不做语义级“矛盾检测”（那要 LLM，且误报会毁掉闸的可信度）。
- 不碰冻结项目；其他项目解冻时吃的是这套问 / 答 / 验收，不是又一轮猜。

## 6b 本会话自证（2026-11-09 20:51）

上一轮“没问就出了四步规格”，正是方案里说的“AI 根本不问不读”。补救可量化的做法：

- 已用 `qn_propose` 落一卷 `方寸-规划判断半-裁决层A`（S1–S5：首战靶子 / 零问题判据 /
  闸口范围 / 种子来源 / 交付节奏），答完才开工。
- 这一卷同时是判断半的**第一次实跑**：题问错了就改题，先别改流程。
- 后续任何规格单，出厂前都要过同一道闸：没附卷 = 不进队列。

**第一次实跑当天就暴露两个真 bug（已修，0.6.11）**：五道题全答完却落成空卷
（`answers.value` 过 contextBridge 抛 `could not be cloned`，`catch` 为空；
`approveDeck` 还允许空卷批准）；反问按钮没有基座（`.ask` 只有 scoped 颜色，
几何全无 → 原生按钮；守卫只扫 `views/` 且只查规则存在，不查几何）。
修法与验证见 `开发日志.md` 同日条目 —— 这两条正是“看起来没问题、其实是假的”的活样本，
也说明后面 S1–S3 的闸必须落在数据层，不能靠界面自觉。
