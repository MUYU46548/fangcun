## 原型里的四个设计判断（比分数重要）

1. **散点矩阵，不是表格。** 横轴 = 工程成本（人月），纵轴 = RICE 得分，**气泡大小 = 触达用户数**。
   原型自己的注脚：「象限按成本 6.5 人月 / 得分 600 切分，看的是**相对位置**；
   P 级按**绝对分数阈值**划分。两者不一致时以 P 级为准——**象限负责解释原因，分数负责决定顺序**。」
2. **容量护栏。** P0 合计 17 人月 ≈ 当季 24 人月的 **71%**，留 29%（7 人月）给线上故障与需求变更。
   原话：「**把排期排满，等于一次 P0 故障就让整季延期。**」
3. **「为什么做，为什么砍」是独立一节。** 分数只是入口，理由逐条写。
   最狠的一句关于被砍项：「它最危险的地方是**听起来很酷**——RICE 的唯一作用，就是把审美冲动挡在排期之外。」
4. **立场写在最显眼处**：「**RICE 只把判断显性化，不替你做决定。真正的取舍在分数之外。**」
   重评触发条件只有一个：**当季容量变动超过 20%**。

**这四条合起来，正好回答了 0.5.0 那两条失真**：失真来自"只算分不写理由"，
而这份原型把理由、容量、相对位置全摆在分数旁边。
