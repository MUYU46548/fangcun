## 一、这一版改了什么

### 1. 新增功能（4 项）

| 功能 | 一句话 | 关键取舍 |
|---|---|---|
| **在途一屏** | 一行一个在途项目，看清「在哪一步 / 下一步 / 卡在谁」 | 数据全部**只读聚合**（契约 + 任务卡 + 执行日志 + git）；读不到一律写「未填」，不替你猜；没进这一屏的项目**按原因分别说明**（"你没勾它" ≠ "它没有未完结任务"） |
| **相关提交** | 任务详情显示"这张卡存续期间，仓库里有哪些提交" | **只读**：只用 `git log`，不 checkout / 不 fetch / 不写任何仓库；异步 `execFile`（第一版用 `execFileSync` 会冻住主进程）；`--grep` 用固定字符串（任务 ID 里的 `-` 当正则会变范围符号） |
| **阻塞链关键路径** | 阻塞视图顶部告诉你「先解哪个最划算」 | 算的是**传递效应**：A 挡 B、B 挡 C ⇒ 解 A 值 **2** 而非 1；算法抽成 `shared/blockers.ts` 纯函数（可被 node 直接断言，不埋在组件里） |
| **返工归因** | 任务卡新增可选字段，三档：需求没拟死 / 选型没论证 / 执行层改不对 | **空值不写进文件** → 旧卡零影响；不是追责，是为了三个月后能回答"哪一环在漏" |

### 2. 修复（5 类）

| 问题 | 真因 | 处置 |
|---|---|---|
| **★ 数组类偏好从来没写进过盘** | 渲染层把 **Vue 响应式代理**直接当 IPC 载荷，`contextBridge` 在「页面世界 → 隔离世界」这一跳就抛 → **报文连预加载层都进不去，主进程日志一个字都没有** | **第三次踩同一个坑**（前两次：启动台"无法启动任何应用"、日志"按钮全炸"）。这次不只打补丁：`saveUiPref` 收口 + 假预加载加 `structuredClone` 校验 + `check-ipc-parity` 第 ⑥ 类断言 |
| 完成/驳回任务的出口说不清 | 不是功能缺失（删除一直在「操作」组），是**出路没说清** —— 终态只剩两个按钮时人不会往下找第三个 | 退回按钮按状态分文案（退回返工 / 退回待办）+ 一句提示讲完三条去向。**没有加第三个按钮** |
| 界面文案 5 处 Markdown 泄漏 | **Vue 不解析 Markdown** → 用户看到字面星号 | 一并修掉假数据（概览卡硬编码"3 条"）、内部标识外露（`active`/`projects`）、术语（判据/门槛→规则）、同一动作三个词（销毁/删除→彻底删除） |
| 卡片日期灰字对比度 3.18 < AA | 颜色**写死在组件里、不在主题令牌里** → 09-29 那轮"六套主题全量调 AA"从它身上漏过去了 | 改用主题次要文字色；`check-themes` 新增「散落在组件里的文字色」一档 |
| 一处非法状态「待处理」 | 那是**日志页的分区叫法**，被手写进了任务卡 | 归正为「待办」；判据收进 `core.illegal_status()`，`doctor` 从此会拦；两侧枚举逐字一致 |

### 3. 清理（13 条死通道）

| 删了什么 | 说明 |

| 备份 UI 残留（3 条） | 被现有接口取代的旧接口（其中一条与 `backup:status` 完全重复） |

死通道 **44 → 31**，预加载暴露面 **190 → 177**。动手前全仓 grep 核查过没有第二调用方。

## 五、一条流程建议（针对"你开始自用了"）

你说本版"作者已经开始自用，会根据自用情况调整"。自用暴露的问题是**最高优先级输入**，但口语描述容易丢。建议定一条规矩：

> **每次报障当场建卡**（哪怕只有一句话标题），修完写结果记录。
> 好处：① 不丢；② 三个月后能回看"哪类问题反复出现" —— 返工归因字段就是为这个准备的。

（这也符合你定的"未完成任务必须落在卡片上，不许只在对话里存在"。）
