# 问卷系统：半成品 → 完整（建议，2026-11-08）

> 提建议的人：Hermes（在绒花墨坊那边干活的 agent）。
> 依据：读了 `desktop/src/main/data/questionnaires.ts`（890 行）、`shared/questionnaire`、
> `QuestionnaireModal.vue`。**不碰代码，只提判据。**

## 先说结论

方寸的问卷**已经做对了最难的一半**：`QAnswer.kind` 有 pick / skip / reject / askback / amend / void 六态，
`QAudit` 有「答案可被反驳」的结论与证据，还有 `approvedAt` / `voidReason` / `costGaps`。
这在别处见不到。

它还是半成品，不是因为缺功能，是因为**答题结束之后什么也不发生**。
下面六条，按“缺了哪一环会让整卷白答”排序。

## 1. 答卷要接决策（最要紧）

现在一卷答完 = `approvedAt` 有值，然后……没有然后。

建议：**整卷批准时，自动生成/更新决策卡**（`decisions.md` 里那种），并把 `decision_id` 回写到答题文件。
RICE 池已经在用 `decision_id` 回链，同一条链，不用新造。

判据：任意一条已批准的答案，都能顺着 `decision_id` 找到“它变成了哪条决定、谁在什么时候拍、什么时候该复查”。

## 2. 题目要能声明依赖

现在的题是平铺的。问 200 题，其中一半会因为前面已经定了而白问 —— 这就是“问卷疲劳”的来源。

建议：每题加 `dependsOn: { id, kind, k }`（只在某题取某个值时出现）。
界面按答案折枝，导出时把“因前置答案而未问”记成 `skip`（现有状态就有），不要留空。

## 3. 要有“问完了”的判据

现在只有「答了几题 / 共几题」，没有「问够了没有」。

建议：把已答答案重放到结论集，看结论是否还变；**连续 N 题（比如 10）不改变任何结论，即宣布收敛**，停止追问。
这是“问全”唯一可执行的判据 —— 否则永远问不完，或者问到一半就开工（我们这半年就是这样）。

## 4. 冲突必须当场回问，不许静默覆盖

`amend` / `void` 已经存在，但缺“新答案与旧答案矛盾”的检测。

建议：每次 `pick` 落盘前，与同卷、以及跨卷同域（同 layer）的答案比对；
矛盾时**不许直接写**，要求补一条 `amend.text`：为什么改（旧答案曾经成立）。
这和绒花墨坊正在做的“素材冲突裁决”是同一条规则 —— 只是那边裁素材，这边裁决定。

## 5. 审计要有到期

`QAudit` 有 verdict（ok / refuted）和证据，但没有“什么时候该复核”。
方寸今天已经有 47 张决策卡、11 条 RICE 挂了 10 天没人回头 —— 前车之鉴。

建议：每卷答完写 `auditDue`（如 +30 天），到期未复核就在界面上标灰，
并把“原答案 + 当时代价”一起摆出来，让人一眼决定：仍然成立 / 推翻。

## 6. 导出的不是卷，是结论页

现在导出的是答卷。人大脑里要的是一页纸：

| 已定 | 待定 | 有冲突 | 已作废 |
|---|---|---|---|
| 一句一条，带 decision_id | 缺哪个前置才知道 | 两边答案 + 谁的裁决 | 原答案 + 作废原因 |

这一页才能替代“大号任务清单”：它只说**结论**，不列任务。
任务是从结论里长出来的，不是反过来。

## 一句话

**问卷系统的完成态，不是“能出题、能答题”，是“答完之后，方寸能据此否决一个方案”。**
做不到否决，它就只是访谈记录 —— 而访谈记录我们已经有 47 张卡了。
