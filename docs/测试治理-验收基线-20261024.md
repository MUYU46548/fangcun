## 2. 分层测试策略

| 层 | 跑什么 | 时长 | 何时跑 | 挂了意味着什么 | 是否合入门禁 |
|---|---|---|---|---|---|
| **L0 编译** | `cd desktop && npm run build`（vite + tsc main + tsc cli，零 TS 错）；`python -c "import tegula"`。**产物新鲜度校验放在这层**：`newest(src) <= newest(dist)` 否则强行 build | ~40s | 每次改动 | 代码不可交付。后面全部无意义，直接中止 | ✅ 硬门禁 |
| **L1 快车道** | `python verify.py`(293) + `scripts/test/check-*.cjs`(8/66) + 9 个 `check-*.py`(261，**新增入列**) | ~30s | pre-push 钩子 / 每次提交 | 契约、模板绑定、IPC 对账、样式规则断了。**这是唯一能在 30s 内给答案的层** | ✅ 硬门禁 |
| **L2 逻辑层** | `scripts/test/e2e-*.cjs` 中除 GUI 的 49 个（2007 断言），4 并发 | ~70s | 每次合并前 / 每批拆分后 | 数据层、主进程、跨语言契约破了。**按文件粒度定位**（每个文件独立进程 + 独立临时目录） | ✅ 硬门禁（允许 env 类重试 1 次，见 §3.4） |
| **L3 GUI 层** | 串行独占：`e2e-renderer-web`(757) → `e2e-renderer`(312) | ~45s | 每次合并前 | 渲染层。**这层禁止 SKIP 通过**（见 §3.4） | ✅ 硬门禁 |
| **L4 重活** | `bench-load`（性能拐点）、`drill-restore`（备份恢复演练）、`dryrun-backup`、`electron-builder` 打包冒烟、安装包升级 | ~5-15min | 每周 / 发版前 | 性能退化、备份不可恢复、装不上 | ⏱ **T+1 或 发版前**，不进合入门禁 |

**回归策略**：L1 全套 = 冒烟集（pre-push 用，30s 给答案）；L2+L3 = 合并门禁；L4 = 发版门禁。**不做"部分回归"**——这项目 2 分钟能全跑，省这 2 分钟不值。

**测试数据与环境**：
- 保留既有好约定并写成纪律：每个 e2e 用 `mkdtemp` 独立临时根 + `FC_TEST_USERDATA` 隔离【实测多处如此】。
- 新增硬纪律：每次 gate 结束后做**残留检测**——`%TEMP%/fc-*` 数量不得比开跑前多；`git status --porcelain` 必须为空（`e2e-git-backup` 会建真 git 仓库，路径算错就会往真仓写）。
- 环境冻结：`node` / electron 44.x / Edge 版本号写进 `gate-report.json`。GUI 层结果只在**同版本**间可比。

## 3. 统一门禁设计（`scripts/gate.cjs`）

### 3.1 文件与入口

```
scripts/gate.cjs            唯一入口
scripts/test/baseline.json  断言数基线（入库，只许涨）
gate-report.json            每次运行产物（gitignore）
desktop/package.json        补 "test": "node ../scripts/gate.cjs"｜"gate": "… --full"｜"gate:fast": "… --fast"（当前无 test 脚本【实测】）
.githooks/pre-push          L0+L1（可 --no-verify 绕过，但写 .git/gate-bypass.log）
```

### 3.2 结构（设计规格，不是实现）

```js
// 任务对象；stage 决定并发与是否独占
{ id, file, stage, estMs, timeoutMs, serial, exclusive, parse: 'RESULT' }

stage0 preflight : dist 新鲜度(newest(src) vs newest(dist))；node/electron/Edge 版本；%TEMP%/fc-* 残留；git status
stage1 build     : npm run build（失败即中止，不跑后面的层）
stage2 fast      : python verify.py ∥ check-*.cjs ∥ check-*.py    [pool=4]
stage3 logic     : e2e-*.cjs 去掉 serial 名单                     [pool=4]
stage4 gui       : web → electron                                 [pool=1, exclusive]
stage5 report    : 聚合 + 基线比对 + 双流输出
```

**串行名单（并行互相踩，依据我实测的端口与真仓库占用）**：端口/进程独占 `e2e-ports`（写死 8753/9100/9999）、`e2e-launchpad-diag`（8090、3000-3004）、`e2e-launchpad`、`e2e-mcp-bridge`、`e2e-mcp-protocol`；真仓库/git `e2e-self-sync`、`e2e-git-backup`；GUI 独占 `e2e-renderer-web`、`e2e-renderer`。

### 3.3 关键判据：RESULT 解析必须四态

现有 `RESULT` 行格式不统一，实测 4 种：`RESULT ${pass} / ${fail}`（36 处）、`RESULT PASS`/`RESULT FAIL`、`RESULT SKIP`（2 处）、`RESULT 0 / 1`（14 处，用法错误兜底）。

```js
parse(out):
  /RESULT (\d+) \/ (\d+)/ → {kind:'assert', pass, fail}
  /RESULT PASS/ → {kind:'assert', pass:1, fail:0}   |   /RESULT FAIL/ → {kind:'assert', pass:0, fail:1}
  /RESULT SKIP/ → {kind:'skip'}    ← 门禁记 NOT-PASS，不记 pass
  无任何匹配     → {kind:'none'}    ← 门禁记 FAIL(noresult)
```

**这条是整套门禁的地基**：`kind==='skip' | 'none'` 一律不进 pass 列。`e2e-renderer.cjs` 那两行 `process.exit(0)` 我一个字符都不改——改门禁不改测试，因为测试的退出码语义（"环境不具备"）本身是有意义的，是**门禁**该拒绝它。

### 3.4 失败分类与重试（解决"不因单个 EBUSY 假红"）

| 类 | 识别 | 重试 | 记法 |
|---|---|---|---|
| `ASSERT` | `fail > 0` | 不重试 | FAIL(assert) |
| `NO_RESULT` | 无 RESULT 行 | 不重试 | FAIL(noresult) |
| `SKIP` | `RESULT SKIP` | 不重试 | FAIL(skip) —— **L3 层拒绝跳过** |
| `ENV` | `fail == 0` 且 stderr 命中 `EBUSY\|EPERM\|EACCES\|ECONNREFUSED\|ECONNRESET` 且无断言失败 | L2 重试 **1** 次（间隔 800ms，换临时目录）；L3 不重试（GUI 重试会叠加崩溃） | 首败记 FLAKY，二次仍败记 FAIL(env) |
| `TIMEOUT` | 超过 `estMs × 4 + 20000`（`e2e-renderer` 单独 60s→120s） | 不重试 | FAIL(timeout) |

**绝不允许**：把 ENV 错误翻译成 PASS。本机 `spawnSync`/`execFileSync` 恒 EBUSY【主理人实测】，所以 gate 内部**只用异步 `spawn`**，并且 gate 自己要做一条自证：启动时先跑一个 `spawn('node',['-e','0'])` 探针，若连这个都超时 → 直接 `GATE ABORT(env)`，不假装通过。

### 3.5 输出：一条流给人，一条流给 AI

- **stdout 只允许两种行**：① 人读表 ② 末尾一行 `GATE_JSON {...}`。失败详情走 stderr（防 AI 把噪声当判据）。人读表固定列宽，只在失败行打 `detail`：

```
GATE PASS  pass=3412 fail=0 skip=0 noreresult=0 shrink=0 flaky=1 files=70/70 131s
 L0 build ok 41.2s | L1 fast ok 28.7s 620/0 | L2 logic ok 71.4s 2007/0 (1 flaky: git-backup EBUSY→重试通过)
 L3 gui  ok 45.0s 1069/0 | baseline ok 逐文件无缩减 | dist ok src 10-24 09:12 < dist 09:14
```
- `--json` 字段：`{verdict, pass, fail, skip, noreresult, shrink, flaky, files, ms, stages[], failures[{file,kind,detail}], versions{node,electron,edge}}`

### 3.6 「门禁通过」的唯一判据（一句话）

> **`FAIL=0 且 SKIP=0 且 NORESULT=0 且 SHRINK=0 且 dist 新鲜`，即 `gate.cjs` 退出码 0，且报告首行 `GATE PASS`。**

五个数字里少一个都不能叫通过。**"全绿"从此指这五个 0，不指 `fail=0`。**

### 3.7 「断言只增不减」怎么自动校验（现在靠 `AGENTS.md:191` 手抄）

`baseline.json` 结构：`{ "schema":1, "total":3435, "files":{ "e2e-logs.cjs":{"pass":218,"path":"…"}, "renderer-web-assert.js":{"pass":757,"path":"…"} } }`

比对规则（三条全过）：
1. **逐文件**：`now.pass < base.pass` → `SHRINK(file)`。逐文件而非只看总数——防"把一个文件拆成两个、总数不变、覆盖面变了"。
2. **文件在场**：baseline 里的文件这次没产出数字（改名/删除/漏跑）→ `SHRINK(missing)`。
3. **零断言即失败**：任一文件 `pass===0 && fail===0` → `FAIL(empty)`，不看基线。专打 B6「空集恒真」和"假桩返回空数组"。

允许降的唯一路径：`node scripts/gate.cjs --update-baseline --reason="拆 X 块，3 条断言随块迁到 e2e-xxx，净 0"`。`--reason` 必填、写进 baseline.json 的 `history[]`、进 git diff 供人审。**没有 reason 的降基线 = 拒绝运行**。

附：新断言必须附反例才能进基线。做法固化成 `--require-counterexample`：`baseline.json` 里每个新增条目带 `"witness": "<commit|说明>"`。这条不是仪式——`docs/app-vue-split-ledger.md` 第 9 块记着真事：719 条断言里，把「只看未完成」整段注释掉**一条都没红**；补了 8 条后精确红 2 条。这就是"没做过反例的断言等于没写"的实证。

## 4. CI 方案

### 4.1 为什么不上 GitHub Actions 托管 runner（硬约束，不是偏好）

1. **托管 Windows runner 没有交互式桌会话**。`windows-latest` 是 Server 镜像、服务态会话。Electron 能靠 `--no-sandbox --disable-gpu --hidden` 勉强起窗口，但本项目有 4 个测试依赖"真桌面"：`e2e-renderer` 真点击（焦点/窗口层级）、`e2e-clipboard`（系统剪贴板）、`e2e-idle-reminder`（`powerMonitor.getSystemIdleTime()`）、`e2e-notifications`（Toast 需已注册 AppUserModelID + shell）。
2. **不可靠的 GUI 结果只会变成假绿**。上面那条的失败模式正是 `loadFile` 失败 → `RESULT SKIP` → 退出码 0（§1.1-2）。托管 CI 最可能的产出是"每天绿油油、真点击层天天跳过"。**会撒谎的闸门比没有闸门更坏。**
3. **成本**：`e2e-renderer` 单次 38.9s【实测】，加 electron 44（~100MB）下载、NSIS 打包、Python 环境，单次 8-15min；且 `build.publish` 指向 GitHub releases，上云等于把发布 token 放进 CI。单人本地优先项目没必要开这个口子。

### 4.2 务实方案：三级，明确各自能说什么

| 级 | 载体 | 跑什么 | 触发 | 它能声称的 |
|---|---|---|---|---|
| **一** | 本地 pre-push 钩子 `.githooks/pre-push` | L0 build + L1 fast（≈70s） | `git push` | "契约与编译没破"。允许 `--no-verify` 绕过，但写 `.git/gate-bypass.log`（时间+diff 摘要），下一轮 gate 报告里显示 `bypass 1`，无法静默 |
| **二** | **自托管**：同一台 Windows 机器上的 `schtasks` 定时 + 手动 `npm run gate -- --full` | L0+L1+L2+L3（≈130s）+ L4 周跑 | 每晚 02:00 + 每次合并后手动 | "全部门禁过"。产物 `gate-report.json` + `notifications/gate-YYYYMMDD.md`（项目已有 notifications/ 机制） |
| **三**（可选，明确降级） | GitHub Actions `windows-latest` | 只跑 `python verify.py` + 全部 `check-*.cjs` + `check-*.py`（纯文本/纯逻辑，**不含 GUI、不含 dist/main 依赖**） | push | "文案/契约/模板绑定没破"。**README 与 commit 模板里写死：此绿不含渲染层，不得据它声称全绿** |

关键：自托管 runner 不是"CI 凑合版"，它就是这项目的 CI——同机、同 Edge 版本、会话完整，`e2e-renderer` 能真跑（本机实测 38873ms 正常出 312/0）。**L3 层的结果只在自托管上可信**，这一点要在团队规范里写死，防止有人拿级三的绿去支撑拆分验收。

### 6.3 「怎么证明拆分没改变像素」——三层，项目已有两层

1. **真点击层**：`e2e-renderer.cjs` → `renderer-main.cjs` 312 条【实测】。证明"点了有反应"。
2. **无头 DOM 层**：`e2e-renderer-web.cjs` → `renderer-web-assert.js` 757 条【实测】，已有几何 + `getComputedStyle`。证明"摆法与计算样式没变"。
3. **新增指纹层**（本次要做，因为它把"757 条断言没覆盖到的那部分"也钉住）：在 `e2e-renderer-web` 里加 `pixel-fingerprint.cjs`，固定条件 = 视口 1440×900 + 固定假数据集 + 固定主题 + `--force-prefers-reduced-motion`。取三个 SHA256：
   - **a. 布局指纹**：全 DOM 节点（按 DOM 序）的 `tagName + rect(4位小数) + display/visibility/color/background-color/font-size/font-weight` 拼串哈希。→ **进合入门禁**（同机同版本，零容差）。
   - **b. CSSOM 指纹**：`document.styleSheets` 全量规则文本按序哈希。→ **进合入门禁**。这条同时解决 §6.1 的"import 顺序"问题：顺序变了 b 必然不等。
   - **c. 整图指纹**：Edge `--headless --screenshot` 出的 PNG 的 SHA256（项目已有 `docs/pv-check-1440x900.png` 先例）。→ **T+1 观测**，不进合入门禁（字体/驱动小版本更新会让整图抖，抖了就变成噪声红）。

判据：**a 与 b 在每一刀前后必须逐字节相等**。不相等的唯一出路是 `--reason` 说明这是有意的视觉变更，并且该变更单独一笔提交（对应 ledger 红线"拆分不许顺带改功能"）。

## 7. 回归风险清单（四刀期间最可能被打穿的三类）

### 7.1 第一类：源码扫描型断言——会变红，更会变真空

**量化**【实测】：22 个文件直读 `App.vue`（`fs.readFileSync` + 硬编码路径）且**未**接 `_sources`；132 处负向判据 `!/x/.test()`/`!.includes()`；37 处字符窗口 `[\s\S]{0,N}`；`check-button-styles.cjs` 把 App.vue 的 `<style>` 当**唯一** CSS 来源（第 127 行）。

**为什么"变真空"比"变红"更危险**：`!/X/.test(rendererSource())` 这类判据，拆走后代码还在这个文件里，所以绿；但下次真有人把它写回来，也照样绿——**它守的东西已经不存在了，而它不告诉你**。变红至少会喊。

**防护（按顺序做）**：
1. 第 0 刀把 22 个文件的路径统一到 `_sources.cjs`，并加 `perFile().length >= 29` 的扫描面下限断言——扫描面缩了会喊。
2. 负向判据逐条改造为**正向定位**：`!/X/.test(src)` → `count(X, src) === 0 && count('<X 该在的地方>', src) === 1`。132 条不要求一次改完，但**每一刀触碰到的文件必须改完**。
3. 37 处字符窗口：跨文件拼接会造假相邻（`_sources` 的文件头注释就是为此加的）。需要"同段相邻"的判据改 `perFile()` 逐文件跑；本机 `autocrlf=true`，字符计数前必须 `replace(/\r\n/g,'\n')`（`_sources` 已做，自写正则的没做）。

### 7.2 第二类：真空绿——断言数没掉，但测点搬到别处了

**成因**：拆分把"被守的代码"和"守它的断言"分到两个文件，断言还在跑、还是绿的，但它现在扫的是一份不含目标代码的文本。

**防护**：
1. §3.7 的逐文件基线（掉数会喊）+ `pass===0 && fail===0 → FAIL`（空转会喊）。
2. **每刀对被搬的块做一次注入反例**，写进 ledger 那一行。ledger 第 9 块已经证明这条不是形式主义：719 条断言里注释掉「只看未完成」的过滤逻辑，**一条都没红**——那三条路径此前实为零覆盖。要求格式：
   `第N刀 · 反例：注释掉 <具体分支> → 精确红 <K> 条 → 已还原（K≥1 才算有守）`
   `K == 0` 时唯一允许的动作是**补断言**，不是放行。
3. 每次拆完，ledger 的"验证"列必须同时写**断言数**和**反例结果**。现在 ledger 只写 `renderer-web 727/0 · e2e-renderer 312/0`，少了反例那一半信息。

### 7.3 第三类：样式与像素漂移

**成因**：3129 行非 scoped 全局样式、1593 个规则块。任何 import 顺序变化都会改变覆盖关系，而这种变化**不会有任何断言红**——757 条 DOM 断言只测它认识的那几个元素。更细一层：`check-themes`（主题可读性）与 `check-button-styles`（按钮规则存在）都是**存在性**判据，不测"谁的优先级高"。样式搬家最典型的坏法是"规则都还在，但被后面的盖住了"。

**防护**：
1. §6.3 的 **b. CSSOM 指纹**进合入门禁（顺序 + 内容任一变化即不等）。这是唯一能自动抓住"被盖住"的判据。
2. "CSS 规则数 ≥1593"作为下限断言。
3. 整图指纹 T+1 对比，人工看一眼 `docs/pv-check-1440x900.png` 这类既有基线图。
4. 若最终仍决定第一刀就做样式外置，**额外**要求：`main.ts` 的 import 数组顺序本身就是断言对象（写死顺序常量 + 断言 import 顺序 === 该常量）。
