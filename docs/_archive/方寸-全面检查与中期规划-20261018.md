## 二、你问的三件事

### 1）「没有撤回选项，狂按 Ctrl+Z 没用」

**属实，而且是两回事叠在一起。**

- **Ctrl+Z 无效**：全局快捷键只接管了 `Ctrl+S`；`Ctrl+Z` **刻意不接管**（`App.vue` 快捷键注释写明：
  "输入框里的原生撤销本来就是对的"）。原生撤销只覆盖**本次输入框里刚敲的字**——保存并关窗之后就无从撤起。
- **没有入口**：`.backup/` 每次写盘都会留一版，但界面上没有任何地方能调出来。
  你看到的工具栏只有「返回 / 主页 / 帮助 / 同步」——那里本来就没有编辑动作，自然也没有撤销。

**今天已补**：日志编辑弹窗底部新增「↩ 撤回上次保存」。
它用 `.backup` 里最新一版覆盖当前文件；**写回前会把当前版再备份一次**，所以撤错了还能再撤回来。
顺带修了一个真 bug：备份文件名原来只到**秒**，同一秒连写两次会撞名、后者覆盖前者
（批量操作、改完立刻撤回都会踩到），现在补到毫秒。

**边界说清**：这是"每条记录的上一次保存"，**不是全站撤销栈**。全站撤销要动每一条写路径
（任务、日志、偏好、备份配置……），风险远大于收益，已单独立卡（`task-20261018-001`）。

### 2）「已完成的日志无法保存编辑内容，是预期行为吗？为了防止篡改？」

**不是防篡改，是历史遗留的守卫与界面不一致。**

- 取证：`logs.ts::updateLog` 里原本有一行 `if (entry.status !== 'active') return 无法编辑`；
  而日志卡上的「✏️ 编辑」按钮**对所有状态都显示**。于是流程变成"给你门、不给你路"：
  改完点保存才吃到拒绝，只能复制出来新建一条。
- 这条守卫来自 2026-09-28「状态单行道」时代（active → completed → archived），
  当时目的是防止状态机被乱改，不是防篡改——日志文件没有哈希、没有签名，手动改文件一样能改。
- **现在改成**：已完成 / 已归档**正文可以改**，但改过就落 `edited` 时间戳，卡面显示「✎ 改过」
  （悬停看具体时间）。生命周期字段（状态 / 完成时间 / 保留期）**不在这张可写表里**，改不到。
  真正的"防手滑"交给 `.backup`，而不是禁止编辑。

> 你手动改好的那份司天日志，我没有动过。

### 3）小米两个端点

已查官方文档（`platform.xiaomimimo.com` / `mimo.mi.com`），你说的没错：

| 方式 | Base URL | Key 前缀 |
|---|---|---|
| 按量付费 MiMo API | `https://api.xiaomimimo.com/v1` | `sk-` |
| Token Plan（中国集群） | `https://token-plan-cn.xiaomimimo.com/v1` | `tp-` / `ttp-` |

**两个都不能互换**：拿 Plan 的 Key 打按量付费端点 = 401，而且报错看不出是端点错了。

**已改进**：
- 设置页拆成两个按钮：「MiMo 按量付费」「MiMo Token Plan」，各自填对端点；
- 模型名改成官方 id `mimo-v2.6-flash`（之前填的是 `MiMo-V2.6-Flash`，大小写与接口不一致，
  这是"一键填完还是连不上"的另一个原因）；
- 界面上直接写明 Key 前缀，并加了一句硬提醒：**按小米条款，Token Plan 额度仅限编程工具内使用，
  方寸属应用后端，应选按量付费**。你要用 Plan 也能填，但界面不会装作没这回事。
- 预设**永不预填密钥**（BYOK 红线，有断言守着）。

## 四、体检发现的风险（按优先级）

### P0 — 地基，建议 2-4 周内动

1. **撤销只做了一条记录的一步**。
   任务卡编辑、待办编辑、批量操作目前都不可撤。`.backup` 对任务卡同样在写，接出来的成本低。
   （卡 `task-20261018-001`）

2. **`App.vue` = 15,009 行**，占 `desktop/src` 全部 34,198 行的 **44%**。
   模板 / 脚本 / 样式全在一个文件里，任何新功能都在同一个文件上加行。
   这不是"代码风格问题"，是**改动风险问题**：一次误改能同时影响看板、日志、设置、项目页。
   （卡 `task-20261018-002`）

3. **Electron 28 已 EOL**（Chromium 120，上游停止安全更新），而桌面端是唯一产品形态。
   当前没有原生依赖（无 node-gyp），升级面可控，但必须在分支上跑完真点击 + 打包自检。
   （卡 `task-20261018-003`）

### P1 — 三个月内

4. **备份只增不减**：`backups/` 已 88MB，38 份整包，没有按份数/体积滚动淘汰；
   附件 58MB 也没有大文件清单。恢复演练有单测（假数据），但**没有用真包跑过一次完整演练**。
   （卡 `task-20261018-004`）

5. **0.3.8 已知问题里两条仍开着**：设置页控件风格不统一；模型通道藏在「设置 → Agent」，
   项目页「AI 规划」点下去发现没配，要自己找回去。

6. **AI 用量只有"看得见"，没有"刹得住"**：能看次数/token，但没有阈值提醒、没有单次上限。
   BYOK 下花的是你的钱，至少要有个"这次贵得离谱"的提示。

### P2 — 半年内

7. **契约主线仍有断点**：「一屏看到六项目在哪一步」是验收线①，但司天这类零卡项目的
   `current` 仍靠执行日志兜底；契约覆盖率需要逐项目推进（契约 Q1-Q4 队列）。

8. **竞品探索组件（REV-007）未落地**：条款已写进契约，但没有 schema、没有页签、没有调度。

### 纸面小问题（不排期，顺手修）

- `llm/config.ts::setConfig` 忽略空字符串 → 用户无法把 Base URL 清空（只能「重置」）；
- `atomicWriteBackup` 这个名字有误导性：它内部就是 `atomicWrite`（备份在 `atomicWrite` 里做）；
- `scripts/check-arch-geometry.cjs` 需要传 HTML 路径才跑，不带参数会以 TypeError 退出——
  默认门禁里没有它，属于"工具能用但不会被跑"。
