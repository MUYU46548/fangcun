## 本版内容

### 1.在途一屏

一眼看清在途项目各自卡在哪，节省心智成本。

项目页签新增第 4 种摆法（旧三种一个字没动）：一行一个在途项目，列出
**终态一句话 / 当前步骤 / 下一步 / 卡在谁 / 健康度 / 任务·日志计数 / 最近提交 / 未提交**。

- 数据全部**只读聚合**：各项目的 `立项契约.md` + 任务卡 + 执行日志 + 文件夹最近提交时间。
- **读不到的地方一律写「未填」，不替你猜**；没进这一屏的项目会**按原因分别说明**
  （「你选了手动指定但没勾它」和「它没有未完结任务」是两句不同的话，不混着说）。
- 健康度机器只给默认值（按提交新鲜度算），点一下可**人工覆盖并锁定**，右键恢复自动。

### 2.相关提交

任务详情新增一节。**只读**跟踪Git情况。只用 `git log`，不 checkout、不 fetch、不写任何仓库。以用户数据安全优先。**方寸本身无遥测，不上传和存储用户客户端数据**。

- 时间窗 = 这张卡的「创建 ~ 更新 + 7 天」；
- 提交信息里**提到本卡 ID** 的（`fix: xxx (#task-20261005-005)` 那类）单独列在最前；
- 读不到时**照实说原因**（没归属项目 / 没登记工作目录 / 不是 git 仓库），不给假数据。

### 3.阻塞视图

- 原来只按"直接挡住几个"分类，现在顶部会给一句建议，并且算的是**传递效应** 。
- A 挡住 B、B 又挡住 C，那解 A 的价值是 **2** 而不是 1。已完成的阻塞源不会被推荐。

作者注：尚待测试，可能还需要几轮更改才更好用。

### 4.返工归因

- 给每轮返工收尾打一枚标签。
- 任务卡新增可选字段「返工归因」，三档：**需求没拟死 / 选型没论证 / 执行层改不对**（可留空）。
- 便于长期规划。旧卡不受影响（空值不写进文件）。

## 其他修复

### 5.数组类偏好从来没写进过盘

现象是零散的：「折叠状态记不住」「设置里的执行 Agent 预设改完会丢」「在途一屏勾一下闪退一下」。
真因是同一个：渲染层把 **Vue 响应式代理**直接当 IPC 载荷，`contextBridge` 在
「页面世界 → 隔离世界」这一跳就抛异常 —— **报文连预加载层都进不去，主进程日志里一个字都没有**，
所以查日志永远干净得像没事。

这是**第三次**踩（前两次是启动台的"无法启动任何应用"和日志创建的"按钮全炸"）。本次不只是打补丁：

- `saveUiPref()` 收口，所有偏好写都过 `toPlain()`；
- 假预加载按真机语义加了 `structuredClone` 校验 —— **以后这类 bug 不再"真机必崩、测试全绿"**；
- 给三方对账扫描器加了第 ⑥ 类断言：**裸传数组/对象型 ref 当场报红**（实测本仓识别 54 个这类 ref，裸传 0 处）。

顺带：此前"数组/对象类偏好"**一个都没落过盘**，修复后首次写入即自愈，**不需要数据迁移**。

### 6.完成/驳回的任务

原版看不懂点什么按钮，让AI改了。

- 「还原」按状态分文案：驳回 →「↩ 退回返工」，完成 →「↩ 退回待办」；
- 终态时加一句提示，把三条去向和各自后果一次讲完（**没有加第三个按钮**）：
  接着做 →「退回」｜先收起 →「归档」（文件移进 archive/，随时能还原）｜不要了 →「删除」（进回收站，可找回）。

### 7.界面文案

未经过全面人工审改，懒得动，后期稳定后再改。

- 修掉 **5 处 Markdown 标记泄漏** —— 界面里写了 `**粗体**`，而 Vue 不解析 Markdown，
  用户看到的是**字面星号**（在途一屏的空屏提示、设置页看板归档说明、技能页两处说明、一处鉴权提示）。
- 修掉一处**假数据**：概览卡原写「3 条任务都没有状态标记」—— "3 条"是硬编码的，
  而它实际表示"这个项目一条任务都没有"。
- 概览卡不再把内部标识（`active` / `projects`）当页签名显示，改中文。
- 术语收敛：「判据/门槛」→「规则」；搜索框的「Enter=自然查询」→「也可以直接敲一句话按回车」。
- 同一动作三个词（「销毁 / 批量销毁 / 删除」）统一为「**彻底删除**」，并补上缺失的悬浮说明。
- **新增守卫 `check-ui-copy`**：界面文案里出现 `**` 或反引号当场报红，防止这类问题第四次出现。

### 8.卡片日期灰字对比度不达标（11px 小字 3.18 < 4.5）

`.card-date.dim` 当年写死了颜色，而它**不在主题令牌里** —— 所以 09-29 那轮"六套主题全量调到 AA"从它身上漏过去了。
已改用主题的次要文字色（跟着主题走），并把**"散落在组件里的文字色"也拉进对比度守卫**（写死的颜色会被当场量出来）。

### 9.状态白名单+一处非法状态归正

`task-mingjian-template-20260925` 的状态写着「待处理」—— 那是**日志页的分区叫法**，被手写进了任务卡。
已归正为「待办」，并把判据收进单一来源（`core.illegal_status`），`doctor` 从此会拦；
两侧的状态枚举还要逐字一致（防止各写各的）。

## 已知限制

- **接线卡里只放「指向性说明」**：`fangcun-bridge` 是"怎么连方寸"的卡，提到别的项目时只写
  「细节以那家的技能卡为准」，**不写对方内部的接入细节**（端口、垫片脚本名那些属于各项目自己的文档）。
- 「相关提交」依赖本机 git 命令；读取失败时界面会显示具体原因（不是空白）。
- 「在途一屏」的"当前步骤"在**零任务卡的项目**上会回落到最近一条执行日志 —— 这是预期行为，会带「日志」标记。
- 安装包未做代码签名，Windows SmartScreen 可能提示"未知发布者"。
- 更新检查走 GitHub Releases，需联网。

## 安装

下载`Fangcun-Setup.0.3.3.exe`运行安装即可，将会启动安装向导。方寸已为开箱即用的桌面端应用，支持覆盖更新与应用内自动更新。`latest.yml`随本`release`一并发布，自动更新依赖它，手动安装请无视。
