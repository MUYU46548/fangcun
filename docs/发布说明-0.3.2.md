## 本版内容

### 1. 设置页：侧边栏分类（取代上一版的"点标题折叠"）

用户原话：「**我希望像各大软件那样用侧边栏页签来分类**，而不是所有设置项挤在长长的名单里。」

- 左侧六个分类：**通用 · 数据与归档 · Agent · 项目 · 备份与恢复 · 诊断**，右侧只显示当前那一类。
- 当前分类记进 `prefs.json`（`fc_settings_tab`），下次打开还停在你上次那一页。
- 「项目方针」从"备份与恢复"里挪到了「项目」类（它本来就属于项目）。
- 上一版的"点标题折叠"已移除 —— 折叠解决的是"太长"，分类解决的是"找不到"，两套并存只会更乱。

### 2. WorkBuddy 可以「自装」接入 MCP 了

用户原话：「**似乎没有让 WorkBuddy 自装接入 MCP 的选项**。」

- MCP 接入清单新增 **WorkBuddy** 行，带「📋 复制配置段」与「🤖 让它自装」两个按钮。
- 方寸**仍然不猜它的配置文件在哪**（它是打包应用，落点不可知，所以不显示「打开配置文件」）；
  自装指令里给一份**通用 `mcpServers` 形状**当起点，并明确写着：
  「若与你家格式不符，按你自己的文档改写，但 `command` / `args` 必须原样保留」。

### 3. 技能维护：修掉版本号漂移 + 加守卫

用户问：「**方寸自带 skill 后续应该如何保持更新和维护？**」——查下来第一件事就是：**它已经在漂了**。

- **实测到的漂移**：`skills/fangcun-bridge/SKILL.md` 里写 `version: 1.2.0`，而 `skills/manifest.json`
  登记的是 `1.3.0` —— 内容对得上、**版本号对不上**，谁也说不清"这台机器上装的到底是哪一版"。
  已统一到 `1.3.0`，并把 `docs/agents/` 那份副本同步为逐字节一致。
- **新增守卫 `check-skills.cjs`（19 条）**，从此这四份副本不会再悄悄分叉：
  - `manifest.version` 必须与 `desktop/package.json` 版本一致（技能随包分发，数字要对得上）
  - 每个技能的 `frontmatter.version` 必须等于 manifest 登记的版本 ← **核心那条**
  - `frontmatter.name` 必须等于 manifest 的 id（改了目录忘改 name 会现形）
  - `docs/agents/<id>/SKILL.md` 副本必须与真源**逐字节一致**
  - 有 `SKILL.md` 却没登记进 manifest 的目录必须报出来（会静默漏装）
- 技能页加了一句直白的维护说明（见下）。

## 自带技能是怎么维护的（回答用户的问题）

三层，都已经是既成机制：

| 层 | 机制 |
|---|---|
| **改技能** | 只改仓库 `skills/<id>/SKILL.md` 的正文，顺手把 frontmatter 的 `version` 与 `manifest.json` 一起改；跑 `node scripts/test/check-skills.cjs` 自检（版本号漂移、副本分叉当场拦下） |
| **发版** | 技能随安装包分发到 `resources/skills/`（`extraResources`）；`manifest.version` 跟 `package.json` 版本对齐 |
| **用户端更新** | **升级方寸 → 启动时自动比对哈希**：Hermes / DSH 侧不一致就重装（幂等，装了就不重复动）；WorkBuddy 这类只能手动导入的，技能卡上有「真源指纹」（md5 前 8 位）供你对账 |

也就是：**你不需要手工维护任何一台机器上的技能副本** —— 只要改了真源、跑了守卫、发了版本，
Hermes / DSH 会在下次启动时光；只有"手动导入型"的 agent 需要你自己拖一次（有指纹可对）。

---

## 已知限制（不藏着）

- WorkBuddy 的配置文件位置本机确认不了，所以方寸**不代写**、也不显示「打开配置文件」——
  它给你的是一条自装指令，由 WorkBuddy 自己找自己的配置。
- 「设置页分类」只是重新分组，不改变任何设置项的行为；升级后默认停在「通用」。
- 安装包未做代码签名，Windows SmartScreen 可能提示"未知发布者"。
