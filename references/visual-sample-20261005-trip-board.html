两个要点：① 日志成了 0 卡项目的唯一数据源 —— 这就是你说「全靠日志记录断点」在一屏上的落点； ② 健康度不能只信机器：司天 3 天前有提交，机器判「活跃」，但真实状态是搁置（预算/时间受限）。 所以这一列做成可点击覆盖，你标过的会带 🔒 锁住，机器不再改它。

④ 裁断入口点右上「⚙ 这一屏显示什么」

机器口径只是默认值。你手动选过就以你的为准，不会再被自动推导覆盖。

收哪些项目

默认「自动」= 按下面判据取。想固定就选「手动」。
勾选状态 = 当前判据算出来的结果（10 个）。你一旦手动改动，就切到「手动指定」并记进 prefs.json —— 默认不写死任何一个项目名，换台机器、换个用户都成立。

判据门槛

默认已按你拍的设定。

显示哪些列

存 prefs.json 的三个键 fc_trip_mode / fc_trip_projects / fc_trip_cols， 走既有白名单字面量校验再落盘；不新增存储引擎、不拿 localStorage 当真相。

⑤ 缺值一律「未填 / —」这是纪律，不是抠门

方寸犯过的老毛病是「界面说假话」（默认值伪装成事实）。这一屏读到什么写什么：
  • 契约没有 → 红框「未填」+ 两个按钮：复制模板（A，给你一份骨架，你去仓库里改）/ 📁 打开 repo（B，直接开目录）。
  • 没有进行中的卡 → 写「— 没有进行中的卡」，不拿"最后一张完成的卡"顶上。
  • 0 张卡也 0 条日志 → 写「— 0 张卡 · 无日志」，并注明「只有提交撑着」。
  • 10 行里 9 行终态未填 —— 这不是这一屏的毛病，是九个项目还没立契约。视图只负责把它摊开。

⑥ 两个我自己拍的小决定不同意就改，我先说清楚

  • 健康度可人工覆盖（司天「搁置」就是例子）。机器只给默认值（提交新鲜度），你点一下就能锁成 活跃 / 搁置 / 休眠 / 完成，锁过的带 🔒，机器不再动弹它。理由：司天这种"在动但冻结"的状态，机器永远算不出来。
  • 日志来源写清楚：「当前步骤」回落到日志时，旁边挂一枚小标签「日志」，让你一眼看出这条不是卡里来的。
