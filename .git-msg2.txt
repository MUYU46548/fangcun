## 但这一轮只修真正会致错的那一半：材料过期

实测契约原文里写着：
- 「**一屏视图不存在**」—— 做完了（`e2e-trip-board` 44 条钉着）
- 「**6 个项目在方寸零任务卡**」—— 早补了

上下文包**逐字照搬**这些字样。于是每个开工的 agent 都读到"一屏视图不存在"，
然后可能去建一个已经存在的东西。**模型不会怀疑上下文包，它只会照着做** ——
一份写错的包比没有包更糟。

`missing` 机制早就在（缺什么要明说），但它只管"有没有"，不管"还算不算数"。
这一轮补的是后者。

## 做法

新增 `shared/contextFreshness.ts`（纯逻辑，可 node 直接断言）：
- `findLastVerified(text)` —— 认 `最后核实：` / `实跑` / `更新：` 三种写法，**取最晚的那个**
  （一段材料里多处日期时，材料新旧由最新的那处决定；取第一个会把"当时的断点"当成材料日期）
- `judgeFreshness(text, today)` —— 三态：过期 / 新鲜 / **判断不了**
- `freshnessNote(label, verdict)` —— 统一措辞；**空串 = 不用提**（新鲜时不加噪音）

三态是刻意分开的：
- **没锚 ≠ 过期**：没日期 = "我不知道它新旧"，过期 = "它确实旧了"。
  合并成一句会让"没写日期"看起来很严重，而"三个月没更新"看起来很正常。
- 没锚的话术里**不许**出现"新鲜/最新/没问题"这类反向保证。

接进两处：契约节（①）与结构地图（③）。
