> **2026-11-20 v2 已落地**：一条记忆 = `## 记忆`（1–2 句 claim）+ `## 证据`（原文逐字）。
> 检索 / 注入 / 列表只碰 claim；证据只在 `memory_read` 时取。
>
> 规划与取舍：`docs/记忆层-v2-规划-20261120.md`
> 竞品调研：`docs/记忆层-竞品调研-20261119.md`
>
> 触发：暮雨「记忆加个开关（默认开启）」「人家是一条记忆就一两句话，加可信度召回比例等参数。
> 方寸的记忆是一大坨，上下文压力太大而且不便于检索」。

## 一、它是什么

**固定核心（≤800 字，由钉住的 claim 生成）+ 原子记忆（claim + evidence）+ 开关。**

- **claim**：`## 记忆` 下 1–2 句，≤120 字（硬上限 200）。这是唯一被检索/注入/列表使用的文本。
- **evidence**：`## 证据` 下原文逐字；长文可放 `memory/lessons|incidents/`，用 frontmatter 的
  `证据` + `证据锚点` 指过去。**原文一个字都不删，只是不再默认进上下文。**
- **它回答**：发生过什么 / 哪条纪律是拿损失换来的 / 哪条能跨项目用。
- **它不回答**：这次该干什么（那是任务卡 `task-data/`）。

### 明确不做

- ❌ 不自动抽取日志/决策/卡/发言（暮雨 2026-11-17 定）
- ❌ 不向量化（REV-015）；不做图数据库
- ❌ 不做双向同步（方寸是唯一真相源，插件来读）
- ❌ 不进 `task-data/`（会被 `parseTask` 当任务卡扫，污染台账）
- ❌ 不进公开仓库（含真实项目名与本机路径）

## 二、目录

```
memory/
  README.md              # 本文件（入库）
  core.md                # 固定核心：由钉住 claim 生成（≤800 字），勿手改
  core.manual.md         # 可选：人工补充（产品规则/环境事实，≤300 字，算进预算）
  index.jsonl            # 派生索引：claim + 元数据，不含证据正文
  claims/                # ★ 原子记忆：一条一个文件（mem-YYYYMMDD-NN.md）
  lessons/               # 证据层：旧纪律原文（格式: 证据，不参与检索）
  incidents/             # 证据层：旧事故原文（格式: 证据）
  2026-11/               # 证据层：旧的按月条目（格式: 证据）
  .backup/               # 迁移/索引备份（扫描时跳过）
```

**索引与 core 都是派生数据**：源文件是真相；`--rebuild` / 记忆页「重建索引」可重算。

## 三、frontmatter 必填字段

| 字段 | 取值 | 说明 |
|---|---|---|
| `id` | `mem-YYYYMMDD-NN` | 稳定引用 |
| `类型` | 事故 / 教训 / 纪律 / 决定 / 偏好 | 筛选；决定默认半衰期 |
| `可信度` | 0–1 | 用户逐字原话+已核实 0.95；用户批准的复盘 0.9；agent 推断 0.7；agent 新写 ≤0.8 |
| `重要度` | 1–5 | 5 = 不可逆损失/安全；4 = 真实损失；3 = 流程摩擦；2 = 偏好；1 = 备忘 |
| `项目` | registry id 或 `跨项目` | |
| `适用范围` | 如 `跨项目` | |
| `状态` | 有效 / 待审批 / 已撤销 | `待审批` 默认检索不返回 |
| `来源` | 用户原话 / 事故 / 文件路径 | 说不清来源的不收 |
| `时间` | ISO8601 带时区 | 排序 / 新鲜度 |
| `复核` | `YYYY-MM-DD` | 可选；>180 天在简报里标"待复核" |
| `半衰期` | 天；0 = 不衰减 | 纪律/决定 0；事故/教训 365；偏好 180 |
| `钉住` | true / false | 固定进 core（≤8 条） |
| `召回权重` | 0.5–2.0 | 手动加权 |
| `编号` | D1 / D15 / W1… | 人读别名 |
| `取代` / `被取代` | 记忆 id | 新事实取代旧事实（旧条 `已撤销`，不删除） |
| `证据` / `证据锚点` | `memory/...` / `D5` | 长原文指针；`memory_read(file, anchor)` 只取那一节 |
| `tags` | 数组 | 检索 |
| `格式` | `2` / `证据` | `2` = 原子记忆；`证据` = 旧文（不参与检索） |

## 四、四条硬规矩

1. **一个文件只讲一件事**。claim 里出现"另外/还有/第二"且明显是另一条规则 → 拆。
2. **claim ≤120 字（硬上限 200）**；超了写入直接拒，细节放证据。
3. **`## 证据` 不许为空**。至少 20 字原文摘录；长原文用 `证据` 指针。删掉原文就是篡改历史。
4. **agent 只能写 `待审批`**（2026-11-19）：`memory_write` 永远落 `待审批`，
   默认 `memory_search` 不返回它；用户在记忆页点「通过」才转 `有效`，点「驳回」转 `已撤销`。
   agent 没有"自己批自己"的写口。

## 五、检索 / 体检

```bash
python scripts/memory.py                    # 全部（按时间倒序）
python scripts/memory.py --type 事故
python scripts/memory.py --scope 跨项目
python scripts/memory.py --q "kill"
python scripts/memory.py --pending          # 只看待审批
python scripts/memory.py --all              # 含已撤销与待审批
python scripts/memory.py --json
python scripts/memory.py --rebuild          # 重建索引
python scripts/memory.py --check            # 校验索引 + v2 格式（非零退出=不合格）
```

**召回参数**（详见规划 §4）：

**排序 = 归一化加权和**（2026-11-24 改，问卷 C1=A 抄 Generative Agents）：
`score = (n相关度 + n重要度 + n新鲜度)/3 × 可信度 × 使用强度 × 权重`，
前三项**各自 min-max 归一化**后相加；**门槛打在 `相关度 × 可信度`（绝对值）上**，不打在归一化分上。

预算：core 800 + 简报 800 = 每会话 ≤1,600 字；检索默认 10 条 / 1,500 字；`memory_read` 默认 8,000 字。
超预算必须报 `truncated` / `dropped`，不许静默少给。

**两条口径（都栽过）**：

- 「筛出来 0 条」≠「库里一条都没有」；「关掉」≠「空」≠「读失败」≠「没连上」。
- `--check` 用 `utf-8-sig` 读索引（Windows 的 BOM 不是坏数据，但坏行必须点名）。

**检索文本只拼内容，不拼 frontmatter（2026-11-24 修）**：

原先 haystack 拼的是整篇 `_raw`，**键名被当内容搜** ——
`--q 格式 / 状态 / 来源 / 证据 / 类型` 各命中 **34/34**，等于"搜什么都能搜到全部"。
现在与 TS 侧 `memoryRank.ts` 的 `haystack()` 同口径：claim + 编号 + tags + id + 证据正文。

守卫：`python scripts/test/check-memory-search.py --self-check`（20 条）
- ① 键名当查询词必须 **< 总条数**；
- ② 真内容（`kill` / `frontmatter` / `worktree`）必须 **> 0**；
- ③ 同一条查询 Python 与 TS 的命中数**必须相等**（两侧各写一套 = 口径迟早分叉）；
- 反例两条：把 `_raw` 拼回去 → ① 精确变红；把 haystack 清空 → ② 精确变红。

## 六、核心与预算

- `core.md` 由 `钉住: true` 的 claim 生成，**默认 800 字，用户可调**（2026-11-24 改，暮雨：
  「预算应该用户可调，不要写死代码」）。设置页「记忆 → 常读记忆字数上限」，区间 **200–4000**，
  存 prefs 的 `memoryCoreBudget`。**预算不只管截不截，更管装得下几条** —— 改了会按新预算重排 core。
  ⚠ 旧实现把 800 当硬上限，钉住一多就静默丢条目，而提示语还说「请减少钉住条目」：
  把设计的约束说成了用户的规定。实测后果：I5 与 I10 被挤出 core，而 I10 正是
  「规矩写在报告里 ≠ 写在闸门里」。不再手抄（手抄 = 第二份真相）。
- `core.manual.md` 可选（≤300 字，算进 800 字预算），只放产品规则/环境事实。
- 归档（证据）**永不自动注入**；`fangcun_context` 只带 core，`memory_briefing` 按需取前 5 条。
- `core.md` 超预算会**报 dropped 条数**，不会静默少给；放不下就在设置里调大预算（上限 4000）。

## 七、开关（默认开）

`prefs.json` 三个扁平键（**不是嵌套对象**——`setPrefs` 是浅合并）：

```json
{ "memoryEnabled": true, "memoryInjectCore": true, "memoryBriefing": true }
```

- 键不存在 = **开**；判断一律 `!== false`。
- **总开关 `memoryEnabled`**：关掉后 agent 五个出口（core / search / read / briefing / write）
  全部返回 `enabled:false`，并说"记忆已关闭；数据还在"。
- **两个子开关（2026-11-24 才真正接线）**：
  - `memoryInjectCore` 关 → `memory_core` 的 `text` 为空、`subEnabled:false`，
    hint 说清「钉住 N 条还在」；
  - `memoryBriefing` 关 → `memory_briefing` 不返回 `items`、`subEnabled:false`；
  - 两者都支持 **`force: true`**：开关的语义是"别自动喂给我"，不是"不许我看"。
    `force` **不越总闸** —— 总开关关着时仍然 `enabled:false`。
  - ⚠ 这两个键在此之前**只有设置页的两个复选框**，后端零消费：点掉它什么都没变。
    守军 `node scripts/test/e2e-memory-switches.cjs`（26 条，含两条精确反例）。
- **记忆页照常可看可管**：开关关的是 agent 自动读写，不是数据锁。
- 关掉 ≠ 空 ≠ 读失败 ≠ 没连上 —— 四种状态四句话，测试逐条钉。

## 七之二、复核提醒（2026-11-24 接线）

`memory_briefing` 的每条现在带 `review` / `reviewAgeDays` / `reviewOverdue` 三个字段，
顶层带 `reviewOverdue` 计数。超过 **180 天**（`REVIEW_DAYS`）的条目会在 hint 里被点名，
要求向用户确认"它还成立吗"，不许当现行规矩直接用。

⚠ **`reviewAgeDays` 认不出日期时是 `null`，不是 `0`。** 0 会被读成"刚复核过"，
反过来"认不出 → 0 → 1970 年 → 晾了 20000 天"会把每条老记忆都标成待复核，提示变成噪音。
未填 `复核` 的条目不标待复核（`null` → `reviewOverdue:false`）。
在此之前 `复核` 字段只被解析、从没被读过 —— 规划 §3.3 那句承诺是空的。

## 八、和 agent 自带记忆 / 插件

| 层 | 谁写 | 生命周期 | 规矩 |
|---|---|---|---|
| 会话上下文 / 压缩摘要 | 框架 | 一次会话 | 工作记忆；重要结论当天提案进方寸 |
| `AGENTS.md` | 人 | 随代码 | 只放指针和 3 条红线，**不复制记忆正文** |
| 会话历史检索 | 框架 | 归档 | 需要时搜，不当长期记忆 |
| 第三方记忆插件 | 插件 | 长期 | **不双向同步**；方寸是真相源，插件来读（REV-015） |
| 方寸 `memory/` | 人 + agent 提案 | 长期、有审批 | 唯一有审批的长期记忆 |

- 联动：`fangcun_context` 注入 core → `memory_briefing(project)` → `memory_search` → `memory_read`。
- 用户说"记住" → agent `memory_write` → 落 `待审批` → 用户点通过。**不能自批。**
- 新事实推翻旧事实：新 claim 带 `取代: 旧 id`；通过后旧条 `已撤销` + `被取代`，不删除。

## 十、导入 / 一键整理 / 批量（2026-11-20 问卷 M1 B / M4 C / M5 A）

- **导入**：JSON 数组，或一条 v2 Markdown（`---` frontmatter + `## 记忆` + `## 证据`）。
  来源必填（条目自己的 `来源`，或导入框里的来源）；**全部落待审批**；重复默认跳过，不覆盖已有文件。
- **一键整理**：**不调模型、不写盘**。方寸把最近日志 + 已完成/驳回任务拼成一份给 DSH 的整理包；
  DSH agent 用 `memory_write` 逐条起草（只能落待审批），用户再审批。
  source 必须逐字等于候选 id；最多 8 条；方寸不再需要任何 API Key。
- **批量**：本页待审批可「全部通过 / 全部驳回」；逐条走 `memorySetStatus`，只改状态、不删文件。
- **测试**：`node scripts/test/e2e-memory-import.cjs`（21/0，临时数据根）；
  界面接线见 `e2e-renderer-web`（导入 / 整理 / 批量三条各钉一次）。
