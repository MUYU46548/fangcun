# 方寸 (Tegula)

**本地优先的多 Agent 任务收口台。** 把任务、执行日志、项目方针对齐到同一个入口，
让“派活 → 执行 → 验收”这条链有明确的落点，不再散落在各个对话窗口里。

本项目**使用 AI 辅助开发**。

如果喜欢本项目，欢迎到[爱发电](https://afdian.com/a/muyu46548B?utm_source=copylink&utm_medium=link)支持我们！

## 下载安装

到 [Releases](https://github.com/MUYU46548/fangcun/releases) 下载最新版 `Fangcun-Setup.<版本>.exe`（NSIS 安装包，Windows x64），双击安装即可。同 appId 覆盖安装，无需先卸载。
当前版本 **0.7.9**（版本号真源只有 `desktop/package.json` 一处）；每一版改了什么见 [Releases 的说明](https://github.com/MUYU46548/fangcun/releases)。

> ⚠ 本仓库**不再随版本控制发布 `docs/`**（执行日志、派工单、交接记录里有真实项目名与本机路径）。
> 所以下面凡是提到"手册 / 免责声明"的地方，入口都在**应用内**，不是仓库里的文件链接。

安装包未做代码签名，Windows SmartScreen 可能提示"未知发布者"，选“仍要运行”即可。为了设备安全，请只从官方渠道下载并核对哈希值。

首次启动会引导选择数据目录：可以新建空白看板，也可以指向已有的 Python CLI 数据目录（`registry.yaml` + `task-data/`）。

> 安装版默认数据目录是 `%APPDATA%\fangcun-desktop`。如果你同时用本仓库的 Python CLI / dev 模式（数据在仓库根），请在 设置 → 数据与归档 → 修改目录 里指向仓库根，两边数据即可统一。

## 它解决什么

| 问题 | 方寸的做法 |
|---|---|
| 任务散落在会话里，换个窗口就忘了 | 任务只在**一处**登记；agent 通过 CLI / MCP 取活与回写 |
| 新会话从零开始，上次干到哪不知道 | **执行日志跨会话接力**：承接上一次的“下一步”与执行 Agent |
| 每个项目的要求靠口头交代 | **项目方针卡**（使命/目标/场景/边界），派活时随任务下发 |
| 装完就忘，看不出做过什么 | **23 个页签 + 应用内帮助手册**：看板 / 待办 / 日志 / 项目 / 阻塞 / 路线图 / 日历 / 归档 / 回收站 / 决策 / 问卷 / 记忆 / 成本 / 技能 / 插件 / 服务… |
| AI 干完不知道算不算数 | **待验收卡 + 判据**：判据可复跑，不是"AI 说好了就好"；"完成 / 驳回"只有**你**能签 |
| 删错就没了 | 删除进**回收站**可还原；归档按文件路径判定；备份包可校验、可还原 |

定位很明确：**任务收口 + 方针载体**。不追"全周期管理平台"。

## AI 是怎么接的（2026-11-20 起口径变了，别按老文章配）

**方寸不自带模型，也不保存任何 Key / 端点。** 需要 AI 的地方，方寸只做一件事：
**写一份派单文件**，由 **DSH 桌面版**在自己的会话里执行——用的是你 DSH 里已经配好的模型。

- 设置页里**没有**端点 / 模型 / Key 的输入框（2026-11-20 前的 BYOK 配置已整体退场，不是藏起来）
- 派单文件经 GUI 签名，只有你在界面上点出来的那一份才会被消费
- 回执与花销：DSH 把自己的用量报回方寸账本，`ai-trace.jsonl` 留痕，成本页可查
- **产出只落「待审批」卡**，你点头才转正

> Hermes 通道仍然保留，但按 2026-11-25 的口径是 **弱支持**：已经接上、偶尔维护、
> **不保证可用**。DSH 是主通道，两条互不相干 —— Hermes 那边没配好**不算故障**。

## 功能一览

- **看板**：7 个状态列，拖拽切换；列视图 / 列表视图 / 信息卡墙三种摆法（卡墙可开“只看未完成”）；按状态 / 项目 / 优先级分组，分区可折叠，终态列默认收起
- **待办**：清单 / 卡片网格两种摆法；设了到期日会出现在日历上
- **执行日志**：跨会话接力、归档分区、批量归档与删除（确认框里会列出**标题**，不让你盲点）、按项目 / 执行 Agent 筛选、一键复制成提示词
  ⚠ **日志对 agent 只读**（2026-11-19 起）：那是你记上下文的私人笔记本，不是 AI 的汇报栏
- **撤销与历史版本**：日志和任务卡都能看历史版本、逐版预览、恢复任意一版（恢复前自动备份当前版）
- **项目 / 作战计划**：健康度总览 + 每个项目的**方针卡**；作战计划页是阶段卡流水线 ——
  agent 起草草案 → 你裁决冻结 → 推进 → 验收。草案**一份一行全部可见**，支持「提成齐的 N 格」批量提成
- **决策台账**：定下来的事记成卡 —— 内容 / 日期 / 出处 + 三态「有效 / 已撤销 / 已合并」，
  跨会话、跨项目防遗忘；「待审批」是唯一需要你动手的一档
- **问卷（问答）**：方寸把"需要你拍板"的问成卷子（互斥选项 + 每项写代价 + 每题写验收线），
  你答完点批准，答案才进决策台账 —— **AI 只能出题，不能替你答**
- **记忆层**：一条记忆一两句话（claim）+ 原文证据分两层，检索只碰 claim；
  按「相关度 / 重要度 / 新鲜度」加权召回，钉住的进 core；预算可在设置页调
- **阻塞 / 路线图 / 日历**：依赖链追踪（算的是**传递效应**，不是只数直接阻塞）、跨天时间段、四处指派入口
- **归档 / 回收站**：归档以**文件路径**为唯一判定标准；删除先进回收站，可还原、可彻底删除
- **通知中心**：每条通知标了**该谁做** —— 「该我做的」默认展开，AI 自己的活折叠但仍在库里、不计未读，
  而且会随派单任务书带给 AI。实测本机 55 条里 38 条是 AI 的活
- **启动台**：登记并一键启动本地应用；**服务与端口只读监控 + 冲突预警**（刻意不提供"杀进程"能力）。
  ⚠ **可选 / 冻结（2026-11-21 暮雨拍板）**：各项目已转桌面端，启动台不是核心工作流，主要留给其他开发者；
  只修“会崩溃 / 会损坏数据”的 bug，**不再加新功能**（文件选择器、路径校验、启动诊断一律不做）。
- **技能安装专区**：把方寸的接线卡装给任意 agent —— DSH 可**直装并自动跟随版本更新**；
  Hermes 弱支持；WorkBuddy 这类落点不可知的，给真源文件 + 真源指纹，由你手动导入或让它自装
- **MCP 接入材料**：按各家官方格式生成配置段（Claude Code / Cursor / Codex / OpenCode / Hermes / DSH / WorkBuddy），
  并支持生成“自装指令”让对面的 agent 自己动手 —— 方寸**不写任何外部应用的文件**
- **备份与恢复**：一键打包（zip + `.sha256` + manifest + 说明 + 恢复脚本）、校验、WebDAV 定时备份、Git 镜像备份；
  **主通道是 Git**（可追溯可回滚），本机包 / 云端 / restic 都是**备用**；
  **密钥永不入包**，恢复前必做 sha256 + 结构双校验
- **帮助手册 / 多主题 / 应用日志**：顶栏“?”进，**视图内**渲染的离线手册（不跳外部页面）；
  六套浅色主题（全部过 WCAG AA）；出错有日志可查

## 项目结构

```
fangcun/                     # 单一 monorepo
├── desktop/                 # Electron 桌面版（主产品）
│   ├── src/
│   │   ├── boot.ts          #     真入口 → dist/boot.js（桌面 / MCP 桥二段式分流）
│   │   ├── index.ts         #     桌面主进程 → dist/index.js
│   │   ├── main/            #     数据层 / MCP / 派单 / 备份 / 记忆 / 通知 / 技能安装
│   │   ├── renderer/        #     Vue 3 界面（views / components / composables）+ 纯逻辑
│   │   └── preload/         #     IPC 桥接
│   └── package.json         #     Node 依赖 + electron-builder（NSIS）
│
├── skills/                  # 方寸自带的 agent 技能（随包分发）+ manifest.json
├── memory/                  # 记忆层规范（数据不入库）
├── tegula.py                # Python CLI 薄入口（agent 集成 / Web 看板）
├── tegula/                  #   核心模块（core / cli / web）
├── templates/               #   Web 看板模板
│
├── scripts/test/            # 回归与守卫（e2e-* + check-* 静态守卫 + verify.py）
├── registry.yaml            # 项目注册表（**不入库**，见下）
└── task-data/               # 任务数据（Markdown + YAML frontmatter，不入 git）
```

> ⚠ `registry.yaml` / `task-data/` / `policies/` / `docs/` / `memory/` 都是**本机使用数据**，不入版本库。
> 所以 clone 下来是一张**空注册表**（`tegula doctor` 会提示你去登记项目），这不是坏掉。

## 快速开始

### 桌面版（推荐）

```bash
cd desktop
npm install
npm run dev            # 热更新调试
npm run build          # 构建（vite + tsc 主进程 / CLI）
cd ..
node scripts/pack.cjs <版本号>   # 打包 NSIS 安装包 → desktop/pkg（发版取件目录）
```

> `desktop/pkg` 是**固定**产物目录（`.gitignore` 已忽略），不要再用
> `electron-builder -c.directories.output=release-<ver>` 一版新建一个目录。
> 版本号必须先改 `desktop/package.json`，`pack.cjs` 会核对不一致直接拒绝。

> 开发调试注意：改主进程 / preload 后必须重启 Electron（渲染层热更、主进程只在启动时读一次）。
> `npm run dev` 的 `dev:electron` 已带 dist 监听自动重启。

> **帮助手册**：装好后点顶栏的“?”打开（离线、视图内渲染）；每个页签干什么、搜索语法、
> 备份恢复都在里面，不跳外部页面。开发态同样可用。

### CLI（可选）

```bash
python tegula.py serve   # 启动 Web 看板（默认 127.0.0.1:8753）
python tegula.py next    # agent 取活（带出项目方针卡）
python tegula.py status  # 项目健康状态（git 活动 + 任务关联）
```

零外部依赖，纯 Python 标准库。

## 数据与隐私

- 所有数据存储在**用户本地目录**（Markdown 文件即数据，可被 git / 网盘直接管理）
- **方寸本身不上传数据**：不注册账号、不内置统计 / 埋点 / 崩溃上报，不向作者服务器回传任何东西。
  会联网的只有两处，且都**由你触发或由你配置**：① 手动“检查更新”访问 GitHub Releases；
  ② 你自己配置的备份通道（WebDAV / Git）
- **方寸不保存任何模型密钥**（BYOK 已整体退场）：AI 走你本机的 DSH 桌面版，密钥在你自己的 DSH 里
- 备份包默认不含任何密钥；数据库与账本外的敏感项只回传"是否已设置"

> 《免责声明与用户协议》的**全文在应用内**（首次启动弹窗，事后可在 设置 → 关于 里重看，
> 当前版本 v1.7）。仓库不再随公开版本发布 `docs/`，所以这里不提供文件链接。
